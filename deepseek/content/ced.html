Input-heavy workloads

A tool returns 50,000 tokens of logs; the model responds with a short decision and calls another tool. In this hypothetical workload, most new tokens are read rather than generated. Making the repeated decode step cheaper leaves the cost of each large tool result. The V4.1 change begins here: which prompt representations really have to pass through the upper layers before they can be used as memory?

In a conventional stack, a high layer makes its keys and values from the representation reaching that layer. It cannot prepare that cache by stopping halfway through the model. V4.1 changes the source of its decoder global memory to an encoder representation. This opens a way to make prompt positions available to upper-layer attention without evaluating every upper-layer transformation at those positions.

Consider a small model whose four layers we number 1 through 4. Ordinarily, constructing layer 4's prompt cache requires the representation leaving layer 3, which in turn requires the preceding layers. Saving layer 4's cache does not let us omit layer 3. If both upper layers instead obtain their global memory from layer 2, prompt positions can become available to their global attention without first passing through the entire upper stack. This must be part of the learned architecture; it is not a rearrangement valid for an arbitrary four-layer transformer. For the released 40-layer model below, we return to the code's zero-based numbering, 0 through 39.

This is the dependency changed by V4.1's causal encoder-decoder. Its 40-layer backbone is divided into a 20-layer causal encoder and a 20-layer decoder. “Encoder” here does not mean bidirectional text encoding. The lower stack remains causal.

The source of decoder global state

Keep the four-layer example in mind. Both upper layers want access to the prompt, but we want to prepare that global memory at the midpoint. A learned projection of the lower stack's output supplies the memory. The current upper-layer state remains free to form its own query.

The first task of the lower stack is to produce a representation for every prompt position. Let B be the number of sequences processed together, T their number of positions, and d=5120 the width of one representation row. Write H_E\in\mathbb{R}^{B\times T\times d} for the width-d encoder representation supplied to global-cache projection. Each fixed batch and position selects one row. This row must be distinguished from the four parallel residual streams carried between blocks; we will make their contraction explicit below.

A cache entry has 512 coordinates. A learned row-map W_l^{KV}\in\mathbb R^{5120\times512} transforms the encoder row into candidate content for decoder layer l. A second map W_l^Z of the same shape supplies the coordinatewise pooling logits when several source positions are combined. Collect their outputs as C_l,Z_l\in\mathbb R^{B\times T\times512}. In the report's notation,

C_l=H_EW_l^{KV},\qquad Z_l=H_EW_l^Z.

The decoder query still comes from its evolving layer state. This makes the global branch resemble attention to an encoded memory, while the local branch continues to use the current layer's own recent state. Sharing a source representation is not the same as making every decoder query identical.

Compressed Sparse Attention 2, or CSA2, adds sharing between cache-owning and cache-consuming layers. An owner creates entries that later layers can read; a consumer uses those entries rather than storing another independent set. The encoder/decoder boundary specifies where the source representation comes from. The ownership schedule specifies how often a projection is independently computed and stored. In the released decoder, one source position produces one global entry, so no multi-position pooling gate is needed there.

Two inputs to a decoder attention layer

For one decoder token, draw two incoming arrows. One carries its current decoder representation: it supplies the query and local entry. The other carries the encoder's representation of the history: it supplies global memory. We will label the stream contraction before following either arrow.

The residual construction from the preceding V4 chapters leaves four rows at each token, rather than one. Suppress the batch index and write these rows as X_{l,t}\in\mathbb R^{4\times d}. The input-mixture coefficients a_{l,t}\in\mathbb R^{1\times4} choose a weighted combination of them. In V4.1 they are carried from the preceding sublayer; the complete forward chapter will follow that timing. Multiplication a_{l,t}X_{l,t} produces one width-d row. The attention sublayer then applies learned RMSNorm across that row's d coordinates.

For example, if the four rows begin with coordinate pairs (2,0),(0,4),(1,1),(3,1) and the supplied mixture is (.4,.3,.2,.1), those two coordinates collapse to (1.3,1.5). RMSNorm subsequently uses all d coordinates, not just the two displayed. The mixture and the normalization are distinct operations. Flattening the four rows would instead produce width 4d=20480, which the cache projection does not accept.

Let x_{l,t}=\operatorname{RMSNorm}_l(a_{l,t}X_{l,t})\in\mathbb R^d be that current attention input. Let e_t\in\mathbb R^d be the encoder-source row for the same position, with its boundary contraction and normalization specified. The decoder's query and local entry use x_{l,t}; the decoder global owner uses e_t. The dependency can now be written without confusing a width-d row with its four-stream residual:

q_{l,t}=\operatorname{Query}_l(x_{l,t}),\qquad c^{\mathrm{local}}_{l,t}=\operatorname{LocalKV}_l(x_{l,t}),\qquad c^{\mathrm{global}}_t=\operatorname{GlobalKV}_{20}(e_t).

Here \operatorname{Query}_l names the layer's projection to 64 query rows of width 512, so q_{l,t}\in\mathbb R^{64\times512}. Each KV operation returns one width-512 entry that serves both key and value roles across those heads. The following chapter develops their projections and the smaller queries used only for selecting global addresses.

The released decoder uses ratio one and has a single global-cache owner at zero-based layer 20. Subsequent decoder layers use that owner's entries; Reindex layers can change their selected addresses. The report's general equations allow layer-dependent projections, while this particular ownership schedule requires only the projection belonging to that decoder owner. The local entries remain separate at every layer.

The distinction explains what can be prepared without evaluating every decoder row. Once encoder outputs are available, global entries can be constructed for all prompt positions. Only the decoder queries and local state still require the evolving decoder representation. During generation, the current token nevertheless traverses both stacks: its final decoder output is needed to predict another token.

The local state does not vanish

Imagine saving the global memory of a long prompt, discarding its decoder rows, and resuming later. The current token can still query that global memory. Its local attention also expects recent decoder entries, which were discarded. Replay is the work of rebuilding those entries.

A single-window replay thus restores the required array shapes without necessarily restoring the original values. This dependency is what we must examine before counting the saved work.

Call the number of positions in a local window w, including the receiving position, and the number of decoder layers D. The receptive field is the set of input positions that could affect a row, directly or through intervening layers. Its local part can extend across roughly Dw tokens. Exact reconstruction must restore the dependencies needed to regenerate a cached row. Bounded replay evaluates a shorter recent segment and accepts the missing dependencies as an approximation.

For a small work count, take a twelve-token prompt and four layers. Full evaluation uses 48 layer-token applications. Two encoder layers for all twelve tokens plus two decoder layers for a three-token tail use 12\cdot2+3\cdot2=30. The eighteen omitted applications are the upper two layers at the first nine prompt positions. This counts where the computation was omitted, before considering the cost of each application.

Generalize that count to a prompt of T positions and an even total of L layers, half in each stack. Full evaluation applies TL layer-token computations per sequence. If T\geq w, reading the prompt through the encoder and replaying a tail of length w through the decoder gives

T\frac L2+w\frac L2.

The first term pays for all prompt positions in the lower half; the second pays for the retained tail in the upper half. For a shorter prompt, replace w by \min(T,w). This is a scheduling model, not a measured FLOP or latency formula. It omits projection work, attention's sequence-dependent cost, replay details and hardware overhead. It explains why an input-heavy workload offers room for savings; it does not establish a universal twofold speedup.

The reference and the serving path

Calling the lower half an encoder saves nothing on its own. The implementation must actually construct the right global memory and omit the upper-layer work that memory replaces. The report describes this serving opportunity; the released minimal loop is useful for inspecting a full traversal. We need to keep those two execution paths distinct when reading the code.

What the minimal forward establishes

To check the claimed saving in code, look for the omitted computation. A loop that still evaluates all 40 layers at every prompt position can demonstrate memory sharing, but cannot demonstrate the proposed encoder-only prompt schedule. This is the distinction to look for in the minimal forward.

In the pinned Python path, Transformer.forward embeds the input, merges any visual rows, makes four residual copies and traverses all 40 blocks. There is no separate encoder-only entry point. The Full attention source calls its compressor with its current collapsed attention input; source layer 20 is the first decoder layer, so this is the boundary at which the decoder's shared global memory is created. The file does not save a separately named encoder-memory tensor and pass it as an additional argument through the upper stack.

This is enough to inspect a concrete full traversal and the single-owner sharing path. To connect its intermediate tensors to H_E in the report, one must identify exactly which collapse and normalization define the boundary representation. Passing the raw four-copy residual in place of a width-5120 source would change that computation. The serving shortcut additionally needs a way to construct global entries for all prompt tokens while restricting decoder attention/FFN evaluation to a tail. That schedule is not implemented by the ordinary full loop.

A replay boundary is an attention boundary

Place a vertical line at the first replayed token. Local arrows crossing that line are unavailable; cached global entries remain available. The following interval writes that picture as an attention mask, keeping the original token positions.

Consider replay beginning at original sequence position s. If the original local window has width w=128, a replayed query at original position i\geq s can use a local key at integer position j only when it lies within the window, has been replayed, and is no later than the query. Those three conditions give

\{j:\max(s,i-w+1)\leq j\leq i\}.

The maximum chooses the later of two left edges: the replay start s and the ordinary window start i-w+1. With replay starting at 100 and a hand-chosen window width four, query 101 can read only positions 100 and 101, even though a full evaluation could also read 98 and 99. This is the concrete dependency removed by the bounded reconstruction.

Original position labels remain in use for RoPE and global-cache addresses. The left boundary cuts off some local dependencies. It does not reset the sequence's absolute position to zero, and it does not make distant global entries unavailable.

Encoder replay handles a cached prefix whose global entries are present but whose local state is missing. Replayed prefix rows regenerate local KV while reading the existing global cache; they do not overwrite those cached global entries with values obtained from the approximation. The uncached suffix then produces its new global and local state. Decoder replay instead sends the prompt's last window of encoder outputs through the upper stack to prepare decoder local state for generation. These two uses of replay have different cache-write responsibilities.

The approximation can propagate beyond the replayed rows: new suffix states depend on reconstructed local context. Consequently, two cache-hit boundaries need not yield mathematically identical later states. The report describes adaptation to decoder replay during post-training and evaluates the resulting quality empirically. No equality proof for ordinary KV reuse can establish the quality of this truncated reconstruction.
