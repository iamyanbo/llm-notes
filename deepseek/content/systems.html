Representing request state

Pause the model after six tokens in a ratio-four compression layer. Attention already has the summary of the first four. The next two tokens have projected values and gates, but no completed second summary. Saving only the entries attention can currently read loses those unfinished contributions. On resumption, token six would enter the wrong group. This is why an implementation needs an explicit account of request state, beyond the final tensors in the forward equation.

The same request also has recent local keys and values at every layer. Those rows describe different layer representations even when several layers share the same global cache. An indexer's selected addresses have a shorter role still: a later Reindex layer can replace them without replacing the underlying entries. A request's state is the collection of information needed to continue its calculation; its fields have different owners and different lifetimes.

RequestState
  token_position
  global_cache[owner]       # completed entries and valid lengths
  local_window[layer]       # recent layer-specific KV
  compressor_tail[owner]    # values and scores awaiting completion
  index_selection[source]  # addresses into a specific global cache
  token_history            # n-gram addressing state

This outline proposes an interface; it is not a class exported by the miniature download. The owner key names the layer that created a global tensor, while layer distinguishes local tensors. A valid length says which allocated entries currently contain meaningful state. The token position labels the next token to process; it does not replace any of these tensors.

Now interleave another request B while A is paused at six tokens. B's first token must begin B's first compression group, rather than becoming the seventh token of A. Each request therefore needs its own unfinished values, scores and valid lengths. Likewise, if a speculative call evaluates three proposals but commits only the first, its retained state must describe exactly that committed prefix. A counter can record the new length, but restoring overwritten local rows or an unfinished group requires the corresponding saved data.

Small configurations must remain meaningful

A small model should preserve the operation we want to examine. Suppose four query heads are divided into two output groups. Each group then contains two heads, and its projection has a well-defined input width. Changing the head count to three while retaining two groups makes that reshape impossible. Similarly, rotating coordinate pairs requires an even rotary width. These are algebraic constraints rather than preferences for round numbers.

Layer schedules introduce a different constraint. Truncating V4.1 after six released layers would leave no decoder global owner at layer 20 and no later Reindex source. A six-layer study therefore needs a new explicit schedule that retains the dependency we intend to study. The miniature uses Full at layer 1, Reuse at 2, a new decoder Full at 3, Reindex at 4 and Reuse at 5. It preserves the sharing pattern at changed dimensions; it does not claim to be a prefix of the released 40-layer network.

Explicitly initialize every learned parameter and deterministic table. The upstream minimal implementation contains torch.empty allocations intended to receive checkpoint values. Instantiating that class without loading or initializing its parameters is not a meaningful random-weight model.

Parallelism adds communication

The single-device equations place no cost on moving a row from attention to an expert. Across devices, that movement becomes an operation. If a router sends a token on device A to an expert stored on device B, B must receive the representation before computing its output, and A must receive the output before completing its residual update. The expert's arithmetic alone does not determine the elapsed time.

Expert parallelism distributes the experts in this way. Tensor parallelism instead divides a matrix operation across devices, requiring communication when partial results must be combined. Context parallelism divides sequence work and must still supply the keys and values required by attention. These decompositions place different edges of the computation graph across device boundaries.

Suppose a token uses a local shared expert and a remote routed expert. The local expert can sometimes execute while the representation travels to the remote expert. Both contributions are still required before their sum is complete. This is the dependency that permits communication overlap; if the next operation needs the remote result immediately, there is no independent work to hide its delay. An overlap measurement must identify both the transfer and the work that proceeds during it.

For this project, a single-device reference comes first. Its grouped operations and ownership model should allow a later sharded version to be compared with it. Multi-device claims require the number and type of devices, interconnect, placement, batch and context lengths.

Timing and memory measurements

Consider two requests with the same model. One supplies a long document and asks for one token; the other supplies a short prompt and generates a thousand tokens. Reducing prompt work can strongly affect the first request while barely changing the repeated decoding work of the second. We therefore need to say which interval is measured. Prefill throughput counts input tokens per second. Time to first token is a duration, usually seconds or milliseconds, including work before the first output appears. Decode latency is the duration per subsequent token step; total request time is the duration of the whole interaction. These define quantities for a measurement, not measurements already obtained here.

Use warmup, synchronize asynchronous device work around timing, repeat measurements and preserve the samples. Report both the workload and the distribution of timings. Concurrent work can change the timings; control or report that contention before comparing kernels.

The same distinction applies to memory. Four-bit codes for 512 coordinates have a 256-byte logical payload before scales, but a float32 tensor containing their decoded values still allocates 2,048 bytes for those coordinates. Rounding behavior and physical packing are separate measurements. The allocator may also reserve more memory than live tensors occupy, and offloaded state still occupies host or storage space. Report the quantity actually counted before comparing it with an analytic cache slope.

Keep the reference when optimizing

An optimized kernel can be fast, finite and wrong in a way that looks plausible. Reversing the residual transport orientation still returns the right shape. Normalizing local and global attention separately still returns a weighted sum. Keeping a readable reference gives us a calculation to compare against before interpreting a discrepancy as a precision tradeoff. Weight-layout conversion needs the same explicit correspondence.

For example, summing float32 terms in a different order can change the last few bits without changing which mathematical sum is intended. A comparison needs a tolerance justified by that numerical change. Conversely, a transposed transport matrix can produce a large systematic discrepancy even when all values are finite. The retained reference gives these two observations different interpretations. The next chapter uses that reference in a composed model; the later experiments distinguish its checked calculations from serving paths that remain to be implemented.
