HCA: make the memory coarse enough to read all of it

CSA keeps relatively fine summaries and spends an indexer pass choosing which ones to read. Another possibility is to make far fewer summaries and read them all. Heavily Compressed Attention (HCA) explores that choice. We save selection work by giving each retained global entry responsibility for a much larger part of the history.

Use eight source positions with one chosen coordinate (0,0,8,8,0,0,0,0). Equal-weight pooling of adjacent pairs retains (0,8,0,0); equal-weight pooling of all eight retains only 2. The coarser entry carries the elevated feature, but no longer lets attention address the elevated pair independently. Learned coordinatewise weights can change the retained value; they cannot restore separate addresses inside one entry.

This is a scaled-down illustration with chosen equal weights. Now apply the same question to V4's released HCA: how coarse is one global entry, and what detail remains in the local window?

The released HCA uses 128 positions per entry, using one content map and one score map, with no previous-block overlap. The pooling operation is the coordinatewise weighted combination from Day 3; its group and source support have changed.

Both modes use shared-KV attention, a sink, inverse query rotation and the grouped return map. HCA changes the memory resolution and removes index selection. With a short prefix, CSA may also retain all completed addresses because their count is below its selection budget; the budget limits longer histories. Putting the V4 modules together

Each main box now names an operation we have developed: learned projections, pooled entries, selected addresses, a shared-KV attention result, an expert mixture or residual transport. We can connect them and check which representation crosses each boundary. Start with V4 Flash. The other variants remain available as references for later comparisons.

Follow one token from its embedding through the attention and expert updates, then through the final stream reduction and vocabulary map. The auxiliary MTP branch receives a separately supplied next-token embedding during training. Its path will be explained below; it is not an automatically accepted continuation.

Token identifiers become residual streams

The input lookup from Foundations supplies one learned vector per token ID. V4 must turn that into the four-stream state expected by the blocks we have constructed. Copying one looked-up vector supplies that initial state; later attention and expert updates can make the streams differ.

Let u\in\{0,\ldots,V-1\}^{B\times T} contain the input IDs: B sequences of T positions, with vocabulary size V=129280. Tokenization has already divided the text into vocabulary pieces; an ID may name a word, part of a word, punctuation or a control token.

An embedding table E\in\mathbb R^{V\times d} has one learned row of model width d per ID. For sequence b and token position t, look up row E_{u_{b,t},:}. The colon denotes all feature coordinates. The resulting tensor has shape B\times T\times d.

V4 copies each looked-up row into four residual streams. With stream index a=0,1,2,3, the initial state is

X^{(0)}_{b,t,a,:}=E_{u_{b,t},:}.

The initial state's shape is B\times T\times4\times d. The streams begin equal; different mixing coefficients and injected updates can make them diverge. There is no additive positional embedding or embedding RMSNorm at this boundary. Position enters in the attention branches we have developed.

One complete attention update

The four-stream state first needs a narrow input for attention, then a way to retain old state and add the returned result. These are Day 2's input, bypass and output connections. The attention function inside them is now the query–memory–selection–value-sum construction from Days 3–5, followed by today's grouped return map.

Follow one token's four rows, X\in\mathbb R^{4\times d}. Its coefficient predictor flattens them to width 4d and produces 24 raw measurements rescaled by the flattened inverse RMS. Separate scales, biases, sigmoid gates and matrix normalization turn them into A\in\mathbb R^{1\times4}, C\in\mathbb R^{4\times1} and B\in\mathbb R^{4\times4}. In these per-token equations, B is the residual matrix; in tensor shapes it denotes batch size.

The predictor uses the flattened scale statistic, but the mixture AX combines the original rows. Apply the attention sublayer's own learned width-d RMSNorm to that mixture. Denoting this normalized row by x and the resulting four-stream state by Y, the update is

x=\operatorname{RMSNorm}_{attn}(AX),\qquad Y=BX+C\operatorname{Attention}(x).

The subscript on RMSNorm identifies its learned gain parameters. It is separate from the flattened predictor normalization. Applied at every position, x has shape B\times T\times d. It supplies the parallel branches below; none of their separate input projections is applied to another branch's output.

Only this final width-d row is multiplied by C and added to BX. The result Y has four streams again. Adding an ordinary residual outside this update would introduce a second path that is absent from the specified block.

Preparing a pooled entry for the cache

Pooling determines which source values enter a summary. Before storing it, V4 also controls its coordinate scale, supplies its positional frame and rounds selected coordinates to a smaller numerical format. The order matters: rounding before normalization is generally a different function from rounding afterwards.

Normalization controls the summary's scale; positional rotation locates its content relative to the query. Those operations are already part of our construction. The released numerical implementation also rounds selected coordinates to reduce precision. The exact formats below can be read separately after this first architecture pass.

Optional precision detail: casts, Hadamard rotation and rounding order

The main local entry follows projection→learned RMSNorm→last 64-coordinate RoPE→nonrotary rounding too, but uses its own token position and has no pooling. Entry normalization and local normalization have different learned gains. The source-position anchor never changes the completed-block visibility rule.

FP8 and FP4 mean eight-bit and four-bit floating-point codebooks: each can represent only a finite set of scaled numbers. To approximate a group of coordinates, choose a positive scale, divide by it, round to representable values and multiply by the scale again. For example, on a chosen unit grid a coordinate 2.6 becomes 3. Rounding creates an error even when we keep the reconstructed result in a wider array.

The indexer's additional transform changes the coordinates presented to rounding. A two-coordinate normalized Hadamard matrix is H_2=2^{-1/2}\begin{bmatrix}1&1\\1&-1\end{bmatrix}. It maps (4,0) to (2\sqrt2,2\sqrt2), distributing the original coordinate across both outputs. More generally its orthogonality, H_2^\top H_2=I, implies (H_2q)^\top(H_2k)=q^\top k for any query and key pairs q,k. V4 applies the analogous normalized transform at width 128 to both indexer queries and keys. The exact dot product is preserved before rounding; separate rounding afterwards need not preserve it.

The minimal source simulates these codebooks by quantizing and reconstructing values, then retains BF16 arrays, where BF16 is a 16-bit floating-point format. Its numerical path therefore includes the rounding error while its allocation does not demonstrate a packed FP8 or FP4 production cache. Linear projections also use the release's specified low-precision weight and activation formats; the branch diagram describes their logical input and output dimensions.

The feed-forward update receives the new streams

The expert sublayer begins with Y, the complete attention update. Its separate predictor generates input coefficients A_F, residual transport B_F and injection coefficients C_F, with the same shapes as their attention counterparts. The subscript F labels this feed-forward update. Its learned RMSNorm also has separate gains.

x_F=\operatorname{RMSNorm}_{ffn}(A_FY),\qquad X^+=B_FY+C_F\left(E_s(x_F)+\sum_{i\in\mathcal S(x_F)}g_i(x_F)E_i(x_F)\right).

The normalized mixture x_F has width d. The set \mathcal S(x_F) contains six routed expert IDs, g_i are their scaled weights, E_i their gated feed-forward functions and E_s the shared expert. Their sum is width d. Injection and residual transport return X^+ of shape 4\times d for this token. This completes one transformer block.

In the current Day 2 illustration, attention changed the two stream rows to (1.75,1.25) and (2.25,.25). Their next mixture was (2,.75), normalized to approximately (1.3242,.4966). The Day 1 expert then computed approximately (2.9260,-2.2079). That example isolated one expert inside a two-stream wrapper. Here the actual V4 block uses four streams and the complete expert mixture, but keeps the same dependency: the second update reads the state produced by attention.

The vocabulary head: turn four streams into next-token scores

The backbone ends with four feature rows per token, while a vocabulary matrix takes one. A fixed average would collapse them, but would always use the same combination. V4 learns a separate final input connection so the retained streams can contribute differently to the prediction. Its result is normalized and mapped to one score per vocabulary ID.

Generate the gains, then combine the supplied rows

For this readout example, supply final stream rows (1.5,.5),(1.5,1),(2.5,0),(1.5,.5). They are chosen states at the head's input, not the two-stream output of Day 2.

Use a toy readout predictor with its dynamic matrix set to zero and biases (-\log3,0,-\log3,0). Apply sigmoid, \sigma(s)=1/(1+e^{-s}), separately to those biases. It gives gains (.25,.5,.25,.5). We omit the small positive gate offset here. The actual predictor can also depend on the final streams; this choice lets us derive the example's gains explicitly.

Scale the four original stream rows and add. The first coordinate is .25(1.5)+.5(1.5)+.25(2.5)+.5(1.5)=2.5; the second is .25(.5)+.5(1)+.25(0)+.5(.5)=.875. Thus the mixed row is r=(2.5,.875). The gains sum to 1.5, since they are independent gates rather than an average constrained to total one.

Map features to vocabulary IDs

The final unit-gain RMSNorm in this example divides by approximately 1.8729, giving \widehat r\approx(1.3348,.4672). Choose a two-by-three vocabulary matrix

W_U=\begin{bmatrix}1&0&-1\\0&1&1\end{bmatrix},\qquad \ell=\widehat rW_U\approx(1.3348,.4672,-.8676).

Its first column scores ID 0 using the first feature; its second scores ID 1 using the second; its third scores ID 2 using their difference. Softmax gives approximately (.6534,.2744,.0722). These are three possible next-ID probabilities, not three feature coordinates. The forward head itself returns logits; the normalization is shown to interpret them.

A decoding rule can now choose an ID, which the input embedding can look up on the next call. The vocabulary matrix is learned separately from that embedding table. It is not an inverse lookup.

The released final-connection predictor

For final state X\in\mathbb R^{4\times d}, flatten its streams to v\in\mathbb R^{4d}. A matrix W_R\in\mathbb R^{4d\times4} predicts four measurements, a learned scalar \alpha scales them and biases \beta\in\mathbb R^4 supply a default. The connection is

a=\sigma\!\left(\alpha\frac{vW_R}{\sqrt{(4d)^{-1}\sum_{j=0}^{4d-1}v_j^2+\epsilon}}+\beta\right)+\epsilon_{hc},\qquad r=\sum_{i=0}^{3}a_iX_i.

Index j runs over flattened coordinates; i selects a stream. The scale is measured from the flattened state, while the weighted sum uses its original stream rows. Positive constants protect the divisor and gates. A learned final RMSNorm and W_U\in\mathbb R^{d\times V} give vocabulary logits. The inference head projects only the last supplied position; a training path can project all supervised positions.

Final connection and vocabulary map: ParallelHead.

MTP fusion: give a further prediction its additional input

Multi-token prediction (MTP) adds an auxiliary training task to the backbone prediction. After the prefix “the”, the ordinary head predicts “cat”. In a recorded sequence “the cat sat”, the next token “cat” is already known during training. An extra block can receive its embedding alongside the backbone state and learn to predict “sat”.

The new input belongs only to the auxiliary path. Feeding “cat” into the earlier backbone head would give that prediction its answer. We retain the original backbone state and supply the additional embedding on a separate branch.

Put the two inputs in compatible coordinates

The backbone supplies four hidden streams; the observed next token supplies one embedding row. Their magnitudes and roles can differ. V4 normalizes the hidden rows and embedding separately, then applies separate learned projections. The two projected contributions can then be added. The hidden normalization works within each stream's features, not across flattened streams.

Continue with the four supplied rows used in the readout example, before their final collapse. For the observed next token, choose embedding row e_{t+1}=(0,1) from the shared input table. Choose identity maps W_H=W_E=I_2 and unit normalization gains for this small fusion example.

Stream 0, (1.5,.5), normalizes to approximately (1.3416,.4472). The embedding normalizes to (0,\sqrt2). The identity maps preserve these normalized coordinates. Adding them gives fused stream 0 approximately (1.3416,1.8614).

Supply that same projected embedding contribution to every stream, while each hidden stream retains its own projected contribution. The result still has four rows, ready for the extra mHC block.

For a general width d, let X_t\in\mathbb R^{4\times d} be the backbone state, e_{t+1}\in\mathbb R^d the observed next embedding and W_H,W_E\in\mathbb R^{d\times d} the two maps. With a four-entry column of ones \mathbf1_4, the understood addition is

Z_t=\operatorname{RMSNorm}_{H}(X_t)W_H+\mathbf1_4\left(\operatorname{RMSNorm}_{E}(e_{t+1})W_E\right).

The first term has four rows. The second repeats one projected embedding across those rows, so Z_t also has shape 4\times d. The numerical trace stops at this fused input; it does not invent a further prediction.

The released auxiliary path applies another mHC block with local attention and MoE, then its own final connection and normalization. It shares the backbone's embedding table and vocabulary matrix, while its fusion maps, block and reduction parameters are separate. Its target under this alignment is token t+2. The inference class expects the caller to supply correctly shifted inputs; it does not construct training pairs or losses itself.

Fusion, extra block and table sharing: MTPBlock.

The next identifier returns to the input

A forward pass ends at logits, not at a chosen token. To generate, apply a selection procedure to the last row. For temperature \tau>0, basic sampling uses the probabilities

p_i=\frac{\exp(\ell_i/\tau)}{\sum_{j=0}^{V-1}\exp(\ell_j/\tau)},\qquad i=0,\ldots,V-1.

The denominator runs over all vocabulary IDs j, making the probabilities sum to one. Temperature rescales scores before that normalization. Greedy selection instead chooses an ID with a maximal logit; it is a different decoding procedure.

For a toy vocabulary of three IDs, logits (0,\log2,\log3) at temperature one give exponential amounts (1,2,3) and probabilities (1/6,2/6,3/6). If the selection returns ID 2, append that ID to the sequence. The tokenizer converts it to its text piece. The new ID then receives an embedding on the next model call.

Each layer constructs the new query and local entry, completes a compressed entry if enough tokens have arrived, and reads the permitted stored state. A 128-slot local ring reuses physical storage: position 130 writes slot 2, but RoPE still uses token position 130. During prefill the temporary attention list contains the supplied token entries followed by compressed entries; during decode the persistent array begins with 128 ring slots followed by compressed entries. The offsets in gathered indices must match the chosen layout.

The selected ID returns through the embedding lookup and the computation repeats. We have now connected the V4 backbone from token IDs to the next distribution.
