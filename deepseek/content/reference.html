A small model that executes the connected graph

The executable V4 miniature checks whether the modules compose into the forward function we assembled on Day 6. A pooling rule can be right while attention gathers the wrong entries; an expert can return the right vector while the residual connection updates the wrong streams. A small model makes those boundaries cheap enough to inspect and test. It uses random weights, so the question is computational agreement and causal dependence, not the quality of generated language.

For today's reading, choose V4 miniature in the controls. It looks up token embeddings, creates four streams, executes six attention-and-expert blocks, reduces the final streams and returns logits at every position. Each sublayer predicts its current mHC coefficients, and the final head predicts a separate reduction. These are the V4 dependencies we have developed this week.

Later comparison: the V4.1 miniature

The same download also contains a V4.1 variant with carried Single-Pass input coefficients, shared cache/index ownership and a final carried mixture. Leave that branch for the following study. Its query-normalization difference is preserved in the code.

The small dimensions are width 16, four query heads of width 8, query rank 8, two output groups, four routed experts with two active, and vocabulary size 32. The context window is four positions. These choices keep the operations inspectable on CPU. They change the model dimensions and attention schedule; the download's correspondence table records each substitution.

For the recorded eight-token input, one embedding row has 16 coordinates. Repeating that row four times changes the representation from shape 1\times8\times16 to 1\times8\times4\times16: one request, eight positions, four streams and 16 coordinates per stream. Each block preserves this outer shape even though its attention and experts temporarily consume a single 16-coordinate mixture. After six blocks, stream reduction returns 1\times8\times16, and the vocabulary map changes only the last axis to 32. We can therefore compare a prediction at any of the eight positions.

The block begins with four rows per token. In the V4 branch, attn_mix predicts the three maps we called A,B,C. collapse computes the input mixture AX; attn_norm normalizes its width-16 row. In each update, transport(x, combination) mixes the old streams with each other. The other term multiplies the sublayer's single output by a gain for each destination stream and adds it back. The two inserted axes in that expression align a gain per stream with a feature row: post.unsqueeze(-1) varies by stream, while y.unsqueeze(-2) supplies the same output row to all streams before scaling. Inspect the coefficient predictor and transport convention

The reference uses a positive iterative Sinkhorn construction with a documented numerical policy. It preserves the transport constraints approximately, without claiming bitwise agreement with the fused production kernel's epsilon handling. A nonsymmetric three-stream test checks source/destination orientation independently of the two-stream illustration.

One denominator for the selected entries

For one request and receiving token, the function below takes query of shape [heads, channels] and entries of shape [visible_entries, channels]. Each entry is shared as both key and value. Recent local rows and selected completed global rows have already been gathered into this single list. Matrix multiplication with entries.T therefore gives one comparison score per head and visible entry.

The scalar test oracle computes exponentials, their shared denominator and each weighted output coordinate independently of this matrix expression. It catches a separate normalization of the two branches or an accidental value contribution from the sink. Other tests exercise incomplete compression groups, the overlapping previous-block channels and inverse rotation at the query position.

The last column appended to logits is the head's learned sink score. Softmax includes that column in its denominator, while weights[:, :-1] removes it before the value sum. For zero query scores, two entries (2,4) and (4,8), and a zero sink score, all three masses are one. The output is ((2,4)+(4,8))/3=(2,4). Dividing only by the two real entries would incorrectly produce (3,6).

Running and checking the miniature

Extract the archive and use an existing CPU PyTorch environment. The recorded run uses Python 3.13.13 and PyTorch 2.12.0+cpu, seed 20261016, one CPU thread and float64 for the numerical comparisons. The commands below run the tests, produce the JSON record and repeat the recorded calculation for comparison.

python -m unittest -v test_model.py
python run.py
python run.py --verify

The 19 tests ask about mistakes that can survive a casual forward run: an extra sink value, a reversed transport matrix, a future token leaking into a prefix, a batch row reading another sequence, or a reused selection addressing the wrong owner. They also check gradients, serialization, pooling, positional identities and the version-specific query normalization. The recorded maximum prefix comparison error is approximately 8.88\cdot10^{-16} for each variant. The raw record retains the exact values and source hashes.

A future-token perturbation leaves earlier logits unchanged within float64 roundoff. Comparing each prefix's final logit row with the corresponding row in a whole-sequence call checks the composed causal function. The loss is also differentiated and its present gradients are checked for finiteness. No optimizer step or training run is performed, so the generated identifiers have no learned linguistic meaning.

The generation loop below uses the last position's vocabulary row, because that row predicts the token after the complete supplied prefix. argmax selects the greatest score's integer ID, and cat appends it along the sequence axis. This is greedy generation: another decoder could sample from softmax probabilities instead. Converting selected IDs to text would additionally require a tokenizer, which the 32-ID miniature does not include.

This loop recomputes the full prefix. Likewise, step retains token IDs and recomputes their concatenation. Prefix agreement therefore does not establish correctness or speed of a separate persistent KV-cache decode engine. The earlier weighted-pooling download independently checks incremental pooling state; combining a full persistent decoder is a further serving implementation.
