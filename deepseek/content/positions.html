RoPE: compare content at different positions

A compressed entry has a source location as well as content. Two similar passages can play different roles because one comes before a change and the other after it. Even when their content vectors agree, attention needs a specified way to use their positions in the comparison. Sharing the key and value adds a second issue: any positional transform of that stored vector also changes the coordinates it transmits.

Hold two content vectors fixed at (1,0). Their dot product is one whether their source tokens are adjacent or a thousand positions apart. The vectors could already contain contextual information, but this comparison supplies no direct measurement of their positional displacement. We need to specify how position enters.

Rotate the pair (1,0) by a quarter turn: it becomes (0,1). Another quarter turn gives (-1,0). If query and key receive turns determined by their positions, their comparison can now change when their separation changes. This is the idea of rotary position encoding, or RoPE.

Use a chosen step of 90 degrees per position to see the geometry. The actual model uses much smaller steps at many frequencies. For an angle \phi in radians, the general quarter-turn calculation becomes the matrix

R(\phi)=\begin{bmatrix}\cos\phi&-\sin\phi\\\sin\phi&\cos\phi\end{bmatrix}.

Here we display a coordinate pair as a column and multiply on the left. The two entries in each output row say how much of each original coordinate contributes.

A query at position 1 and key at position 0 now have dot product zero. Moving both forward one position gives query (-1,0) and key (0,1), again with dot product zero. The absolute positions changed, but their displacement did not.

Rotations are orthogonal: the transpose reverses the rotation. If q,k are unrotated query and key pairs with angles \phi_t,\phi_j at receiving position t and source position j, then

(R(\phi_t)q)^\top R(\phi_j)k=q^\top R(\phi_j-\phi_t)k.

The equality follows from R(\phi_t)^\top R(\phi_j)=R(\phi_j-\phi_t). At a fixed angular frequency \omega, the difference is (j-t)\omega. The comparison therefore depends on displacement through a rotation, as well as on the content coordinates. A single frequency is periodic; it does not uniquely encode every possible distance.

V4 rotates only the last 64 of each width-512 main query or stored KV vector. These 64 coordinates form 32 adjacent pairs, each with its own frequency. The first 448 coordinates remain unrotated. The dot product adds their content comparison to the contributions from the rotary pairs.

One stored vector, two roles

Using one stored vector as both key and value removes an independent value cache. It also couples two operations: rotating the key for comparison rotates the value that will be transmitted. A relative-position comparison can therefore still send an absolute-frame vector into the weighted sum. V4 brings that result into the query's frame so its rotary coordinates can depend on relative position too.

Return to the toy source at position 0 and query at position 1. The transmitted source pair is (1,0). Shift both positions forward: their comparison stays the same, but the stored source pair becomes (0,1). Thus the transmitted pair changes its absolute frame even though the displacement did not change.

Undo the query's rotation on the transmitted pair. In the original case, rotating (1,0) by −90 degrees gives (0,-1). After the common shift, rotating (0,1) by −180 degrees gives the same pair. The following trace isolates this source before multiplying it by an attention weight.

For any source's unrotated pair c_j, this inverse rotation gives

R(-\phi_t)R(\phi_j)c_j=R(\phi_j-\phi_t)c_j.

The same inverse rotation acts on the whole weighted sum. Linearity lets us apply it to each contribution for this explanation, with its attention weight unchanged. Only the rotary coordinates are affected. This removes the common positional frame; it does not invert the attention sum or commute through arbitrary learned matrices.

At the end of Day 5, follow both roles: a source pair rotates at its source anchor for the key comparison, enters the weighted value sum in that frame, then receives the inverse query rotation. The result depends on the relative angle. This completes one main-head output; combining the many head outputs is Day 6's first task.

A compressed entry uses its current block's starting token position as its rotary anchor. For example, the entry covering current block 4…7 rotates at position 4 and becomes available at position 7. Its anchor determines its angle; the independently derived completion rule prevents an earlier query from reading it. Array slot 1 is not substituted for token position 4.

Choosing the angles at long positions

The toy 90-degree step repeats after four positions. That is useful for seeing a rotation, but a poor way to distinguish a long history. Real rotary coordinates use several frequencies, so different pairs turn at different rates. Extending the range then introduces another choice: stretching all those frequencies also changes comparisons between nearby positions.

The rotation rule needs an angle for each coordinate pair. Let r=64 be rotary width and k=0,\ldots,31 the pair index. A positive base \theta sets angular frequency \omega_k=\theta^{-2k/r}, giving angle t\omega_k at token position t. Here \theta is a frequency base, not an angle. As k increases, the pairs rotate more slowly.

Dividing every frequency by 16 would let a longer displacement produce an old angle, but would also alter the fastest local comparisons. The released construction, called YaRN, instead retains the fast region and interpolates toward divided frequencies in the slow region. We can state that choice by counting complete rotations over the original length T_0=65536. Pair k makes about T_0\omega_k/(2\pi) rotations. Solving for the index that makes \beta rotations gives the boundary

b(\beta)=\frac{r\log(T_0/(2\pi\beta))}{2\log\theta}.

The natural logarithm appears from solving the exponential frequency rule. The configured rotation counts are \beta_{fast}=32 and \beta_{slow}=1. The code sets lower boundary l=\max(0,\lfloor b(\beta_{fast})\rfloor) and upper boundary h=\min(r-1,\lceil b(\beta_{slow})\rceil). Floor rounds down and ceiling rounds up.

Define \operatorname{clip}(s,0,1)=\min(1,\max(0,s)), which confines a number to the unit interval. The ramp u_k=\operatorname{clip}((k-l)/(h-l),0,1) runs from zero to one between the boundaries. If they coincide, the implementation replaces the zero separation by 0.001. With extension factor f=16, corrected frequency is

\omega'_k=\omega_k\left((1-u_k)+\frac{u_k}{f}\right).

Before the transition, u_k=0 retains the base frequency. After it, u_k=1 divides that frequency by 16. Halfway through, the multiplier is 1/2+1/32=17/32. Angles are then t\omega'_k. The schedule changes frequencies, rather than waiting for a position beyond T_0 before switching rules.

V4's compressed-attention layers use base 160000 with this correction. Its pure-local layers use base 10000 without the correction. A compressed entry uses its block-start token position in the same schedule. These rules specify the numerical angles; the quality of predictions at long distances also depends on the trained model.

Grouped output projection: return the heads to the residual state

Grouped output projection connects the attention heads to the residual update. Day 5 produced one vector per head; Day 2's output connection expects one vector of model width. We need to combine those head outputs before adding their contribution to the streams. This is the first connection in today's complete V4 assembly.

Concatenating all the heads and applying one dense map would solve the shape problem. The difficulty is its size: many wide heads make a very wide input. V4 first reduces separate groups, then lets a final map combine their reduced results. We should inspect what this saves and what it removes.

Reduce two groups before joining them

For a small projection example, supply two four-coordinate groups (1,2,3,4) and (5,6,7,8). These are chosen head-output coordinates at the return map's input, rather than the two-coordinate result from yesterday's separate example. Suppose we want four output coordinates.

Choose a four-to-one map P_i=(1,0,0,0)^\top for each group i=0,1. The maps have separate parameters, chosen equal here. They retain the first coordinate of each group, giving 1 and 5. Concatenation simply joins these into (1,5).

A final learned map can now mix the two summaries. Choose

W_O=\begin{bmatrix}1&0&1&0\\0&1&0&1\end{bmatrix},\qquad (1,5)W_O=(1,5,1,5).

The first maps contain eight coefficients in total, and the second contains eight. A direct eight-to-four map would contain 32. But changing the discarded coordinates 2, 3 or 4 cannot affect this chosen output: the final map sees only the two summaries. Grouping and reduction restrict the function; they do not reproduce every dense map at lower cost.

In the released construction the first maps learn richer mixtures, but each still reduces its own group before information crosses between groups. The final result has model width, so it can enter Day 2's output connection.

General grouped map and the released Flash dimensions

Let h be head count, c head width, g group count, r_o reduced width per group and d model width. Group i has row o^{(i)} of width hc/g and map P_i\in\mathbb R^{(hc/g)\times r_o}. The superscript labels a group:

o'=\operatorname{concat}_{i=0}^{g-1}(o^{(i)}P_i),\qquad y=o'W_O,\qquad W_O\in\mathbb R^{gr_o\times d}.

The parameter count is hcr_o+gr_od, compared with hcd for a direct map. Flash uses h=64,c=512,g=8,r_o=1024,d=4096: 67,108,864 coefficients instead of 134,217,728. Each first map is 4096→1024. The count compares matrices, not measured execution times.

We can return attention's output to the model. Before stacking the blocks, we need one more attention mode: HCA, V4's coarser alternative to the CSA memory we have developed.

What the constructions imply

We have three distinct coordinate operations: rotate a query or stored pair at its position, inverse-rotate the attention result at the query position, and project grouped head outputs back to model width. Rotation preserves the pair's Euclidean length, and applying its inverse recovers it. The first grouped map acts independently on each group; a matrix displaying all its coefficients has zeros between groups, followed by a final map that can mix their summaries.

This finishes the attention path: construct queries, choose entries, combine their values, remove the query's rotary frame and return to model width. The expert transformation and residual wrapper are already available. We can now compare HCA and assemble the complete V4 computation.
