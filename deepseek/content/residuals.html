Try simpler residual connections first

An ordinary residual connection carries one working row for each token, adding the result of each new computation to it. Day 2 asks what we could do with several working rows for that same token. We could keep different combinations of earlier results available, and let the network learn how the next computation reads and updates them.

Three choices will recur: which mixture of the old rows enters a sublayer, how the old rows travel past it, and how its returned update is added back to the rows. The sublayer still receives one input row. When it is an expert mixture, its selected experts share that mixed input; Day 1's router chooses the experts and weights their outputs inside that computation. Attention has its own learned connections. We will build these choices gradually, then constrain the bypass so repeated mixing does not amplify the carried state.

Consider the expert we calculated on Day 1, and call that known function F. It receives a row and returns another row of the same width. We still have a choice to make: how much of its output should enter the representation passed to the next layer?

Keep the expert's input x=(1,2) and its computed output. Write u for that output, so we can discuss the connection without repeating all three expert projections:

u=F(x)\approx(5.5666,3.8227).

The ordinary residual connection from Foundations §6.3 adds the full update. Call its result r:

r=x+u\approx(6.5666,5.8227).

The following sublayer receives this new row. The expert learned the function that supplied u; the connection gave that output a fixed multiplier of one. We can begin by making that one choice adjustable. For this first comparison, keep the expert's matrices fixed and change the connection around its computed output.

First attempt: adjust the size of the update

Suppose we want a smaller change. Keep the original row and add half the expert's output:

x+\tfrac12u\approx(1,2)+(2.7833,1.9113)=(3.7833,3.9113).

A multiplier of zero would keep x; a multiplier of one would recover the full residual result r. Let the multiplier be a number \lambda that training can adjust. The connection becomes

x\longmapsto x+\lambda F(x).

This already gives us a useful control: how strongly this sublayer changes the carried row. A learned scalar gate is a researched design in its own right; ReZero studies such gates initialized at zero. We do not need several streams to learn an update strength.

What has stayed the same is the form of the retained state. After addition, we carry one row containing the chosen mixture. We will return to that choice after examining what happens if we also adjust the other path.

Second attempt: adjust how much of the old row is carried

We could halve the old row as well as the update. That gives a different result:

\tfrac12x+\tfrac12u\approx(.5,1)+(2.7833,1.9113)=(3.2833,2.9113).

Call the old-row multiplier \mu, while \lambda continues to multiply the update. We now have two adjustable numbers:

x\longmapsto\mu x+\lambda F(x).

This lets the connection reduce an old representation as new computation is added. But the old path passes through many layers. To examine that path alone, temporarily suppose every sublayer returns zero. Follow just the old-row multipliers, with no normalization applied to that path. One layer then leaves \mu x, two leave \mu^2x, and four leave \mu^4x.

A multiplier of one carries the row unchanged in this test. Repeated halves shrink it, while repeated twos amplify it. A freely adjusted connection can therefore change the scale of the carried information through depth. This does not rule out learning the old-row strength; it gives us another property to control. When we later let several rows mix, we will examine the same issue for matrices.

Third attempt: keep an earlier row available

Return to the actual expert result r=x+u. Suppose one later sublayer should use the original row x, while another should use the updated row r. Choosing one stored mixture now provides just one of these explicitly. A direct alternative is to retain both rows.

We could concatenate their coordinates into one long vector:

[x,r]\approx(1,2,6.5666,5.8227).

Both representations are present, but feeding this whole vector into the next expert changes its input from two features to four. The gate and feature matrices from Day 1 each had two rows, one for each input feature. They would each need four rows to accept this wider vector.

Keeping every successive result would also make the stored state grow with depth. Retaining earlier representations is a possible choice, but we would like to separate how much state we keep from the width of each expensive transformation.

Read one row while retaining two

We can keep x and r as two rows, then form a two-feature input whenever a sublayer needs one. Start with their average:

\tfrac12x+\tfrac12r\approx\tfrac12(1,2)+\tfrac12(6.5666,5.8227)=(3.7833,3.9113).

This is exactly the input produced by our first attempt with a half-sized update. Substituting r=x+u explains the agreement:

\tfrac12x+\tfrac12(x+u)=x+\tfrac12u.

The next sublayer sees the same numbers in both constructions. Their retained states differ: the first stores one mixed row; the second still holds both the earlier row and the full updated row after the read. A different later connection can read a different combination of those two stored rows.

For the comparison below, choose \lambda between zero and one. The single-row construction retains x+\lambda u. The two-row construction retains x and r, and reads (1-\lambda)x+\lambda r. Moving the control changes the chosen read; it does not train the expert.

There is still a design question. We want a fixed number of retained rows, and a rule for updating them after each sublayer. Simply starting with identical copies and adding the same output to every copy would leave them identical. We need to specify which mixture a sublayer reads and how its result changes the different rows.

We have reached that question through simpler connections: a scalar update gate, a scaled old path, and a wider retained state with a narrow read. These calculations describe the choices each construction makes available. Whether a particular choice improves training is an experimental question. The next subsection examines Hyper-Connections as one researched way to put those choices together.

The numerical expert is the Day 1 worked calculation. Scalar-gated residual background: ReZero. The subsequent HC construction is from Hyper-Connections. The intermediate experiments here are an explanatory development, rather than a claimed chronology of the papers.

Maintain and connect several streams

The preceding experiments separated the retained state from the input to a sublayer. Hyper-Connections (HC) uses a fixed collection of retained rows and learns the connections between those rows and the sublayers. Each retained row is called a stream. All the streams at a position belong to the same token.

A sublayer reads a weighted combination of the streams, computes one output, and contributes that output to the streams in separately chosen amounts. Connections on the carried paths also let existing information move between streams. The sublayer's own input and output keep their usual feature width.

DeepSeek V4 uses four streams, initially four copies of the same token embedding. Their updates can differ, so later sublayers can read different combinations of the representations that develop. We will first work with two streams and chosen connection settings, before studying how V4 constrains and predicts those settings.

Work through one HC update

For HC's connection arithmetic, choose a small current state with rows (1,2) and (0,1) for one token. This is a new numerical case: the two rows are given current values, rather than the particular before-and-after pair in §2.1. Keep these values fixed as we examine the connections. The function F is still the worked Day 1 expert, with its same weight matrices.

For this pass, combine half of each current row to make the expert's input. Run the expert once. Add half of its output to stream 0 and its full output to stream 1. The drawing shows the whole pass before we name any of its connection coefficients.

Follow the blue paths around the outside: the two original rows reach their additions separately. In the middle, their mixture supplies the expert's input and produces one new output. At the bottom we again have two rows. A following sublayer can choose a mixture of these new rows, so the choice remains available as computation continues.

There are two different amounts being chosen here: how much of each stream the expert reads, and how much of its output each stream receives. We will work through those choices using the values in this drawing, then allow the old rows to mix along the outer paths too.

Choose what the expert reads

Call the current rows x_0 and x_1, and collect them in a matrix X:

X=\begin{bmatrix}x_0\\x_1\end{bmatrix}=\begin{bmatrix}1&2\\0&1\end{bmatrix}.

Each row belongs to the same token; its two columns are features. The expert expects two features too. Giving it all four coordinates would change its input width. Instead, the connection combines the rows by multiplying each by a number and adding matching coordinates. Our choice in the drawing gives

\tfrac12(1,2)+\tfrac12(0,1)=(.5,1.5).

We can change these two multipliers without changing the expert's matrices. Taking one whole copy of stream 0 and none of stream 1 would recover the input (1,2) used on Day 1. Allowing the network to learn the multipliers makes the input mixture adjustable.

Definition 2.1

An input coefficient row A=(a_0,a_1) specifies how much of each current stream enters the sublayer. For stream rows collected in X, its input is

AX=a_0x_0+a_1x_1.

Our average has A=(\tfrac12,\tfrac12). The expert's computed output is F(AX)\approx(2.6342,2.1415). This is the single output shown in the centre of the drawing. Displayed values are rounded to four decimal places; the additions use the unrounded expert output.

Choose how much each stream receives

If every stream received the same addition, equal streams would remain equal. A later layer would then have identical rows to choose between. Separate output multipliers let the rows develop differently even though the expert was evaluated once.

In the drawing, stream 0 receives half of the computed output and stream 1 receives the full output. Add these contributions to the original rows:

\begin{aligned}\text{stream 0: }&(1,2)+\tfrac12(2.6342,2.1415)\approx(2.3171,3.0707),\\\text{stream 1: }&(0,1)+(2.6342,2.1415)\approx(2.6342,3.1415).\end{aligned}

These are the two rows at the bottom of the drawing. Stream 0 has received a smaller contribution from this expert call. A later input mixture can favour that row, favour stream 1, or use both.

Definition 2.2

An output coefficient column C=(c_0,c_1)^{\mathsf T} specifies how much of the returned output row u=F(AX) is added to each stream. The two contribution rows form

Cu=\begin{bmatrix}c_0u\\c_1u\end{bmatrix}.

The drawing uses C=(\tfrac12,1)^{\mathsf T}. Its input and output multipliers are chosen to make the calculation readable. We will examine how V4 predicts its connection coefficients in §2.5.

Allow the carried rows to exchange information

So far, the outer paths have copied each old row to its own addition. We can also let those paths connect the streams to one another. A destination would then carry a mixture of the old rows before adding its share of the expert output. This allows information already in one stream to reach another directly, even when the expert supplies no update.

Keep the same original state X. Let destination 0 carry three quarters of stream 0 and one quarter of stream 1:

.75(1,2)+.25(0,1)=(.75,1.75).

Let destination 1 carry one quarter of stream 0 and three quarters of stream 1, giving (.25,1.25). These mixtures replace the unchanged old rows on the two outer paths. They are formed directly from X, alongside the expert computation.

Definition 2.3

A bypass coefficient matrix B specifies the carried mixture for each destination stream. Rows identify destinations and columns identify source streams. The carried state is BX.

The choice we just worked through is

B=\begin{bmatrix}.75&.25\\.25&.75\end{bmatrix},\qquad BX=\begin{bmatrix}.75&1.75\\.25&1.25\end{bmatrix}.

Add the same expert contributions as before. Destination 0 now becomes (.75,1.75)+\tfrac12(2.6342,2.1415)\approx(2.0671,2.8207). The changed value comes from the changed outer path; the expert's input and output have stayed the same.

We can collect the whole connection rule. AX is what the sublayer reads; CF(AX) distributes what it computes; BX carries the old state. Write X^+ for the rows after addition:

X^+=BX+CF(AX).

The result still has two rows, ready for the following sublayer. This is HC's contribution: the model can learn how layers read, share and carry representations while each sublayer continues to process a single row. V4's manifold-constrained HC adds restrictions to these connections so that repeatedly carrying the state remains stable. That is the question for §2.3.

The general dimensions and the papers' notation

Let n be the number of streams belonging to a token and d the feature width of each row. Their state X has shape n\times d. DeepSeek V4 uses n=4; our example used n=d=2.

The input coefficients A form one row of n numbers, so AX has shape 1\times d. The function F returns a row of that same width.

The output coefficients C form a column with n entries. Multiplying this column by the returned row gives n rows of width d. The bypass B has one row per destination and one column per source, hence shape n\times n. Both paths therefore return the shape of X.

With one stream and coefficients A=B=C=1, the equation becomes the ordinary residual update x^+=x+F(x). The original HC paper treats residual wiring as a special case in §3.1.

The mHC paper calls V4's input map \mathcal H^{pre} and its bypass map \mathcal H^{res}. It stores the output coefficients as a row \mathcal H^{post} and transposes that row to form the column that V4 calls C.

Why constrain both rows and columns?

In §2.2, the bypass carried the old rows while the expert supplied a new update. We allowed the bypass to mix those rows. How much freedom should that mixing have? It should let the streams exchange information without multiplying up the old state at every layer.

Keep the same state: stream 0 holds (1,2) and stream 1 holds (0,1). For this experiment, let the expert return zero. Then X^+=BX+Cu reduces to X^+=BX. Any change we see comes from the bypass alone.

Follow one feature through the bypass

The bypass applies the same stream coefficients to each feature. For example, taking three quarters of stream 0 and one quarter of stream 1 gives .75(1,2)+.25(0,1)=(.75,1.75). The first feature was calculated from 1 and 0; the second from 2 and 1. These are separate sums.

We can therefore follow just the first feature while we compare bypass rules. Its two values form the first column of our existing state:

Call this column v. It contains one value per stream. Multiplying it by B shows exactly what the full operation BX does to that feature. We will start each comparison from this same column.

First attempt: make each row sum to one

Suppose each stream simply carries 1.2 times its own value. Our first column becomes (1.2,0)^\top. Apply that rule again and it becomes (1.44,0)^\top. This is the old-row multiplier from §2.1, now written as a matrix:

We want mixing to have a different effect: a destination could receive some of each old stream, with the coefficients adding to one. Taking .75 of one source and .25 of the other does this. Taking 1.2 of a source does not.

Requiring a row sum of one is not quite enough, though. The coefficients 2 and −1 also sum to one. Applied to our sources, they produce 2\cdot1-1\cdot0=2. We have exceeded both starting values without adding any expert output.

Require the coefficients to be nonnegative as well. Each destination then receives a weighted average of the old values, so its value stays between them. With sources 1 and 0, every destination must lie between 0 and 1. A coefficient of zero is allowed; copying a single source is one possible average.

Second attempt: let every destination take an average

Now let both destinations copy source 0. Each uses coefficients (1,0), so both obey our averaging rule:

No individual value grew beyond 1. But source 0 has been copied twice, and source 1 has disappeared. Before the operation, the mean across streams was (1+0)/2=.5. Afterwards it is (1+1)/2=1.

Why care about this mean? The ordinary residual bypass carries the old state unchanged. We are allowing the streams to exchange that state, and would like to retain its mean while doing so. Here the baseline level of a feature changed even though the expert added nothing. Keeping every destination within the old range does not prevent that change.

Look down the highlighted first column of the matrix. Its two coefficients sum to 2: source 0 contributes a full copy to each destination. The second column sums to 0: source 1 contributes nowhere. Row sums describe what one destination receives. Column sums describe how much one source contributes across destinations.

Also make each column sum to one

Instead of sending all of source 0 to both destinations, send .75 to destination 0 and .25 to destination 1. Split source 1 the other way: .25 to destination 0 and .75 to destination 1. Each source's coefficients now total one, and each destination still receives an average.

The output values are .75 and .25. Their sum is still 1, and their mean is still .5. Source 0 has been shared between the destinations rather than copied in full to both. This is the bypass matrix we used at the end of §2.2.

The preservation is not peculiar to the values 1 and 0. Let the two source values be p and q. Adding the two outputs gives

(.75p+.25q)+(.25p+.75q)=(.75+.25)p+(.25+.75)q=p+q.

Each pair of coefficients in parentheses is a column sum. Making both sums one retains each source's total contribution. Since we keep the same number of streams, preserving their sum also preserves their mean.

Definition 2.4

A square matrix is doubly stochastic if its entries are nonnegative, every row sums to one, and every column sums to one. For a bypass matrix, write B_{ij} for the coefficient from source stream j to destination stream i. Then

B_{ij}\geq0,\qquad \sum_jB_{ij}=1,\qquad \sum_iB_{ij}=1.

Restricting the bypass to these matrices is the constraint in manifold-constrained hyper-connections, or mHC. It permits mixing while preserving the mean of each feature across streams. This is the choice developed in mHC §4.1.

What happens at the next layer?

The next bypass begins with the previous one's output. Reusing our .75/.25 matrix, the first application gives .75 and .25. The second gives .75\cdot.75+.25\cdot.25=.625 at destination 0, and .25\cdot.75+.75\cdot.25=.375 at destination 1. Their mean is again .5.

We have retained the mean, but the two values are getting closer. Their difference began at 1, became .5, and then .25. A bypass can satisfy the constraint while reducing differences between streams. It does not preserve every detail of the old state.

At a diagonal coefficient of 1, the bypass copies each stream unchanged. At 0, it swaps them. At .5, both destinations receive the same average immediately. All three preserve the mean. The .75 setting mixes more gradually. In a model, successive bypass matrices can differ; if each obeys the constraints, each step still averages its input values and preserves their mean.

Why the combined squared size cannot grow

Preserving the mean alone would allow the values 1 and 0 to become 2 and −1: both pairs have mean .5. To measure large positive and negative values without cancellation, add their squares. For the original column this gives 1^2+0^2=1; for (2,-1)^\top it gives 2^2+(-1)^2=5. This sum is the squared Euclidean length of the column.

Copying source 0 twice also increases this measure: (1,0)^\top has squared length 1, whereas (1,1)^\top has squared length 2. Our doubly stochastic matrix instead produces .75^2+.25^2=.625. We can prove that its squared length never increases, for any source values.

Begin with one destination taking fraction t of value p and fraction 1-t of value q, where 0\leq t\leq1. Compare the square of that average with the average of the squares. Expanding and subtracting gives

tp^2+(1-t)q^2-\bigl(tp+(1-t)q\bigr)^2=t(1-t)(p-q)^2\geq0.

Thus squaring an average gives no more than averaging the squares. Apply this to both destinations of our matrix:

\begin{aligned}(.75p+.25q)^2&\leq .75p^2+.25q^2,\\(.25p+.75q)^2&\leq .25p^2+.75q^2.\end{aligned}

Add the inequalities. The coefficients of each source's square add to one, so the output's squared length is at most p^2+q^2.

The same argument works with more streams. Let v_j be source j's value for one feature, and y_i=\sum_jB_{ij}v_j the value at destination i. Nonnegative row coefficients summing to one give the averaging inequality y_i^2\leq\sum_jB_{ij}v_j^2. Summing over destinations and using the column sums gives

\sum_i y_i^2\leq\sum_j\left(\sum_iB_{ij}\right)v_j^2=\sum_jv_j^2.

For completeness, that general averaging inequality follows by expanding 0\leq\sum_jB_{ij}(v_j-y_i)^2=\sum_jB_{ij}v_j^2-y_i^2. The row sum and definition of y_i give the equality.

Apply the bound separately to every feature column. Repeated doubly stochastic bypasses cannot increase their combined squared size. The input-dependent coefficient predictor and the added expert or attention output are further parts of the block; this linear-path calculation is not a bound on the complete block's derivative or a proof of training stability.

We chose the coefficients by hand here. To learn them, we need a construction that keeps them within these constraints.

Learn the bypass without losing its constraints

The .75 and .25 entries in our bypass were chosen by hand. We would like training to adjust how the streams share information. But if we simply adjust those four entries, a change that helps one destination can spoil a column total. The averaging and conservation properties we just established would no longer hold.

We can separate what is learned from what is used as a coefficient. Let the learned quantities be unrestricted scores for the connections. After calculating the scores, convert them into a matrix that obeys the constraints. Training can change the preferences; the conversion keeps the bypass within the allowed family.

Start with the averaging rule we already know

A row softmax, as in Foundations, gives positive coefficients adding to one. It would solve the destination's averaging problem. We still have to check how much each source contributes across destinations.

For a hand calculation, choose score rows (0,\log2) and (\log3,\log4). Exponentiating gives positive amounts (1,2) and (3,4). They are not yet shares of an average: their row totals are 3 and 7. Divide the first row by 3 and the second by 7:

For example, the first entry becomes 1/(1+2)=1/3. Every destination now receives an average. But source 0 contributes with total coefficient 1/3+3/7=16/21, while source 1 contributes with 2/3+4/7=26/21. We have met only one side of the requirement.

Correct the sources, then check the destinations again

Divide every entry in the first column by 16/21, and every entry in the second by 26/21. This gives each source a total contribution of one. The top-left entry, for example, becomes (1/3)/(16/21)=7/16.

The column totals are now correct. Unfortunately, the destinations have acquired totals 7/16+7/13=203/208 and 9/16+6/13=213/208, approximately .9760 and 1.0240. Dividing columns changed the entries that had made each row sum to one.

We have not lost the reason for the first operation. It tells us what to do next: divide the rows by their new totals, then check the columns again. Continue alternating the two corrections. For a strictly positive starting matrix, these Sinkhorn iterations converge to a matrix with both row and column totals equal to one.

The inspector begins after the two divisions above. Advance once to correct the rows again, or move through the later divisions. DeepSeek V4 uses 20 iterations; our counter counts each row or column division separately, so 20 pairs give 40 divisions. A finite calculation approximates the constraint. Both displayed errors matter.

Does normalization leave anything for training to change?

It does. Our starting amounts produce a bypass with diagonal entries about .4495 and off-diagonal entries about .5505. Raising the score from source 0 to destination 0 gives that connection a stronger preference. Normalization must accommodate it while keeping the other totals correct.

Changing one score changes several final coefficients. In two streams, once a diagonal coefficient is fixed, the row and column constraints determine the other three. The normalization leaves a family of possible bypasses, rather than forcing every score matrix back to the same average.

Let the connections respond to the current streams

Learning a fixed bypass would let different layers prefer different mixtures. Every token reaching one of those layers would still use the same connection coefficients. There is another possibility: use the current stream values to decide how to connect them.

Keep our two rows (1,2) and (0,1). Compare this state with the same rows exchanged between streams. Their average is (.5,1.5) in either case. But the first feature is larger in stream 0 in the original state and in stream 1 after the exchange. A rule that sees only the average cannot distinguish those situations.

A measurement that keeps track of the streams

Give the coefficient predictor both rows in a fixed order. Writing their coordinates end to end gives v=(1,2,0,1). This flattening retains which value came from which stream. It adds no new features and takes no average.

As with Day 1's router, a learned column of weights can form a scalar measurement. For an inspectable example, choose w=(1,0,-1,0)^\top. It subtracts stream 1's first feature from stream 0's first feature:

vw=1\cdot1+2\cdot0+0\cdot(-1)+1\cdot0=1.

After exchanging the streams, the same weights give 0-1=-1. The average row stayed unchanged, but this measurement reversed sign. The model can learn other columns to respond to other combinations of the retained coordinates.

Separate the pattern from a common change of scale

If every coordinate becomes ten times larger, our measurement becomes 10 instead of 1. A sigmoid applied to that larger score could approach its upper limit simply because the whole state grew. We would like to control that common scale before deciding a connection's strength.

Divide the measurement by the root mean square of the coordinates it read. In our state, the squared coordinates add to 1+4+0+1=6. Their mean is 6/4=1.5, and its square root is about 1.2247. Multiplying the state by ten also multiplies this divisor by approximately ten:

The normalized measurement is about .8165 in either case. DeepSeek V4 adds \epsilon=10^{-6} inside the square root so a zero state still has a positive divisor. With that constant, scale cancellation is approximate. Call the normalized measurement z:

z=\frac{vw}{\sqrt{(1^2+2^2+0^2+1^2)/4+\epsilon}}\approx .8165.

Keep a learned default, and let the state adjust it

A connection can have a useful default even when this measurement is zero. Give its score a learned offset \beta. To control how strongly the state changes that default, multiply z by a learned scalar \alpha. The score is \beta+\alpha z.

At \alpha=0, the connection ignores this measurement and uses its default. Allowing a small nonzero multiplier adds a dependence on the state. V4 initializes these multipliers small. For our calculation, choose \beta=0 and \alpha=.5, giving score 0+.5(.8165)\approx .4082.

We still need a coefficient that can multiply a stream row. V4 uses the sigmoid for input coefficients, keeping them positive and bounded. Applying it to this score gives about .6007. Its implementation adds a small positive floor of 10^{-6} to protect against a sigmoid rounding to zero. The resulting coefficient A_0 multiplies stream 0's original row when the sublayer input is assembled.

Exchange the stream rows in the control. The measurement changes sign, and this input coefficient falls to about .3993. Turn off the state-dependent part: both arrangements then use the same default coefficient, approximately .5. These are different connections for different states, produced by the same chosen predictor parameters.

Produce the other connections in the same way

One measurement has supplied one coefficient. The other source needs its own input coefficient. Each destination needs an output coefficient, and each source–destination pair needs a bypass score. Separate columns of the predictor's weight matrix supply those measurements.

V4 converts an output score with twice the sigmoid. At a neutral score of zero, this gives a multiplier of one, so a stream can receive a full copy of the returned update. The bypass scores need the coupled row and column constraints instead: reshape them into a square table and use the Sinkhorn conversion from §2.4.

Collect the predictor in matrix notation

With n streams and d features in each, the flattened state v has nd coordinates. Put the measurement columns into W_H\in\mathbb R^{nd\times(n^2+2n)}. Our four-entry w was one column of the two-stream, two-feature version of this matrix.

All columns share the input RMS divisor. Index the flattened coordinates by a and collect their normalized measurements in the row z:

z=\frac{vW_H}{\sqrt{(nd)^{-1}\sum_{a=0}^{nd-1}v_a^2+\epsilon}}.

The input, output and bypass groups each have a learned dynamic multiplier and learned offsets for their individual scores. Split z into groups of sizes n,n,n^2, apply those multipliers and offsets, then use the conversions in the table. In destination-row/source-column order, reshape the last group to an n\times n table before Sinkhorn. Let the second computation use what the first changed

A transformer block uses attention and then its feed-forward computation. The connection rule must therefore run twice. The second computation should use the state produced by the first; otherwise it would never see the change that attention just made.

We can follow that dependency with the two-stream state we already know. Keep the hand-set connections from §2.2: A=(.5,.5), bypass diagonal .75 and off-diagonal .25, and output multipliers C=(.5,1)^\top. Hold them fixed for this trace so that we can follow the changing state. V4 gives attention and the expert mixture separate predictors for their connections.

Control the size of the row entering the computation

The input mixture is r=.5(1,2)+.5(0,1)=(.5,1.5). Doubling both input coefficients would give 2r=(1,3). The two rows have the same relative coordinates, but a linear map would make measurements twice as large on the second row, changing the subsequent nonlinear computation.

V4 divides this mixed input by its own root mean square before the attention or expert function. For r, the squared coordinates average to (.5^2+1.5^2)/2=1.25. Division by \sqrt{1.25+10^{-6}} gives approximately (.4472,1.3416). Doubling the input also approximately doubles its divisor:

This removes a common multiplicative scale while retaining the relative pattern. Unlike the layer normalization in Foundations, it does not first subtract the coordinate mean. Learned gains then let each coordinate acquire its own scale.

Definition 2.5

For an input row r of width d, RMSNorm divides by its root mean square and applies learned coordinate gains \gamma. Coordinate a is

\operatorname{RMSNorm}_{\gamma}(r)_a=\gamma_a\frac{r_a}{\sqrt{d^{-1}\sum_{j=0}^{d-1}r_j^2+\epsilon}}.

The index j runs through the row's features; \epsilon>0 keeps the divisor positive.

Use unit gains in this example. The coefficient predictor in §2.5 normalized a measurement using all retained coordinates. Here we normalize the two coordinates of the one mixed input. Each divisor belongs to the row actually being read.

Write the two updates as one block

Let F_{attn} include attention and its mixed-input RMSNorm. Use suffix attn for its connection maps. It produces

Y=B_{attn}X+C_{attn}F_{attn}(A_{attn}X).

Let F_{expert} include the expert mixture and its own RMSNorm, with connection suffix expert. The second update is

X^+=B_{expert}Y+C_{expert}F_{expert}(A_{expert}Y).

In V4, the attention predictor reads X and the expert predictor reads Y. Each produces its own input, output and bypass maps. Our trace held the connection maps fixed and replaced the expert mixture with one known expert to isolate this sequence.

Using input coefficients from the preceding update

Day 2 gave each sublayer a learned mixture of the residual streams. V4.1 keeps that role but changes when the mixture is predicted. This is the first of today's two dependency changes: prepare the next mixture during the current update, then examine how the encoder can prepare global memory for the decoder.

Why change the mixture's timing? In V4, the current predictor must inspect all the streams before its input coefficients are ready. Only then can the implementation apply those coefficients to read the streams into one narrow row. The coefficient reduction makes the input read wait.

Try using coefficients already prepared by the preceding update. With two chosen streams (1,0) and (0,1), carried coefficients (.8,.2) immediately supply input (.8,.2). While reading those streams, the predictor might produce new coefficients (.3,.7). Save them for the next update. Using them immediately would instead read (.3,.7) from this state, so the timing change defines a different learned function.

Write X_l for the stream state entering update l; here attention and expert updates receive successive indices. The predictor \mathcal H produces input coefficients A_l, bypass matrix B_l and output gains C_l. The current bypass and output gains still act on this update. Only the input read uses the preceding coefficients:

X_{l+1}=B_lX_l+C_lF_l(A_{l-1}X_l),\qquad(A_l,B_l,C_l)=\mathcal H(X_l).

The function F_l includes the current sublayer's input normalization. The first attention update uses the initial coefficients (1,0,0,0). Attention predicts the input coefficients used by its following expert update; that expert update predicts the ones used by the next attention layer.

Known input coefficients let a tile of the streams contribute to input mixing while it also contributes to prediction of the new coefficients. A fused kernel can combine this traversal with residual transport. Single-Pass mHC names that implementation opportunity. Its speed depends on the actual kernel; the changed dependence is already visible in the equation.
