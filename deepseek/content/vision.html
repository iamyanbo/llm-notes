An image is a grid before it is a sequence

The input so far consists of text token IDs. To answer a question about an image, the model also needs information that those IDs do not contain: shapes, spatial arrangement and visual measurements. Reading the labels on a chart is insufficient to determine its trend. V4.1 therefore learns visual representations from pixels and projects them into rows that can enter the language sequence.

Consider two charts with the same axis labels, one rising from left to right and one falling. Their text alone cannot distinguish the answer to a question about the trend. Nor would a single average of their pixels preserve the arrangement. Even a two-value patch (0,1) has the same mean as (1,0), although projection onto (1,-1) distinguishes them. Learned patch projections can preserve several such local distinctions.

Keep that two-pixel contrast in view. Choose a map with columns (1,-1) and (1,1). The first feature measures a left/right difference; the second measures their sum. Our two patches become (-1,1) and (1,1). They agree in total brightness and differ in arrangement. The learned patch projection has many more inputs and features, but performs this same kind of weighted combination.

A patch embedding groups a small square of pixels, places its channel values in a fixed one-dimensional order, and applies a learned projection. With patch side p and three colour channels, each patch starts as a vector of width 3p^2. The released vision encoder uses p=14, so that width is 3\cdot14^2=588. Its learned map produces d_v=1024 feature coordinates per patch. Pixel-channel coordinates and learned feature coordinates have different roles, even though both are arrays of numbers.

A vision transformer processes those patch representations with within-image attention. Two-dimensional rotary position encoding accounts for row and column coordinates. This bidirectional image processing is separate from the language backbone's causal mask.

One patch row, from measured pixels

The first learned map receives actual pixel measurements. Let H_p and W_p be the patch-grid height and width after the released resizing and padding procedure. The image then has pixel height H=14H_p and width W=14W_p. Its channels are converted to red, green and blue (RGB), divided by 255, then normalized by subtracting .5 and dividing by .5. A channel value 0 becomes -1, 255 becomes 1, and 127 becomes approximately -.00392. Values are stored in the 16-bit BF16 format. Image padding uses grey RGB values (127,127,127); this differs from the zero padding of final features before unshuffle.

Number patch rows r=0,\ldots,H_p-1 and columns c=0,\ldots,W_p-1. Row-major spatial order visits every column of row zero, then every column of row one, and so on. Patch (r,c) therefore has sequence index rW_p+c. Within a patch, flattening visits its red 14\times14 plane, then green, then blue, with each plane also in row-major order. Denote the resulting row by p_{r,c}\in\mathbb R^{588}. All vectors in this chapter act on matrices from the left. A learned matrix W_P\in\mathbb R^{588\times1024} and bias b_P\in\mathbb R^{1024} produce the initial feature row z^{(0)}_{rW_p+c}:

z^{(0)}_{rW_p+c}=p_{r,c}W_P+b_P.

A single output coordinate is a sum of 588 weighted channel values plus its bias. This map can retain contrasts between positions within a patch, unlike the average used in our earlier example. Its width alone does not determine which contrasts were learned.

One complete vision-transformer layer

The contrast map sees inside one patch. It cannot yet tell whether a line continues into the patch on its right. The vision transformer supplies that missing communication: each patch asks about the other patches of the image, updates its features from their values, then applies a feed-forward transformation. Spatial coordinates tell those comparisons which direction separates the patches.

Collect the N=H_pW_p patch rows entering one layer in Z\in\mathbb R^{N\times1024}. There are 32 such layers. The first operation is RMSNorm across each row's 1024 features: divide by its root mean square with \epsilon=10^{-6} inside the square root, then multiply by a learned width-1024 gain. No statistic is pooled across patches. This epsilon differs from the language backbone's configured 10^{-20}.

An affine map with matrix shape 1024\times3072 and bias width 3072 reads those normalized rows. Split its output into three sets of 1024 coordinates, then each set into 16 heads of width 64. These are queries Q, keys K and values V, each of shape N\times16\times64. All three come from the same normalized input; they are not successive transformations of one another. Q and K receive the spatial rotations defined next, while V supplies features to be transmitted.

Fix head h=0,\ldots,15. Its rotated query and key matrices are \widetilde Q_h,\widetilde K_h\in\mathbb R^{N\times64}; its value matrix V_h has the same shape. Their product \widetilde Q_h\widetilde K_h^\top is an N\times N score matrix: receiving patches index rows, candidate patches index columns, and the transpose aligns the 64 coordinates for dot products. Dividing by 8=\sqrt{64} supplies the usual head-width scaling. The output O_h\in\mathbb R^{N\times64} is

O_h=\operatorname{softmax}_{\mathrm{rows}}\!\left(\frac{\widetilde Q_h\widetilde K_h^\top}{8}\right)V_h.

The row softmax exponentiates each score and divides by that receiving row's sum over all candidate patches. Multiplication by V_h takes the resulting weighted sum of value rows. There is no causal text mask within the image. Concatenating the 16 head outputs gives width 1024. An affine output map with matrix shape 1024\times1024 and a width-1024 bias returns that width, and its result is added to the original Z. Call this residual sum Z'.

A second learned row RMSNorm supplies U\in\mathbb R^{N\times1024} to the feed-forward sublayer. Two bias-free maps W_G,W_U\in\mathbb R^{1024\times2816} form a gate branch and a content branch. SiLU applies a\mapsto a\sigma(a) to each gate coordinate, where \sigma(a)=1/(1+e^{-a}). The symbol \odot below multiplies matching coordinates of the two width-2816 branches. A final map W_D\in\mathbb R^{2816\times1024} returns width 1024, and the layer's output Z'' is another residual sum:

Z''=Z'+\bigl(\operatorname{SiLU}(UW_G)\odot UW_U\bigr)W_D.

The result enters the next vision layer. A final RMSNorm follows layer 32. These residual updates retain patch rows while allowing their features to depend on other patches; the subsequent grouping therefore combines contextualized features, not untouched pixel patches.

How the two spatial axes rotate a head

We now have patch-to-patch comparisons. Moving a feature one patch downward should differ from moving it one patch to the right. Two-dimensional RoPE puts those two displacements into different coordinate pairs. Start with the row/column split; the exact head layout below tells us where each rotation goes.

Two patches can be one row apart or one column apart. A position rule should retain that distinction before their features are compared. The vision attention map produces query and key heads with 64 coordinates each. Its two-dimensional RoPE divides one such vector into halves of 32 and pairs coordinate j in the first half with coordinate j+32 in the second, for j=0,\ldots,31. The first sixteen pairs use the patch's row position; the remaining sixteen use its column position. These pairings differ from the adjacent-coordinate complex pairs used by the language attention implementation.

A single rotation frequency would repeat the same angular scale in every pair. Instead, define sixteen frequencies \omega_k=10000^{-2k/32}, for k=0,\ldots,15. The index-zero frequency is one; later indices turn more slowly per grid step. At patch row r and column c, define angle \alpha_j=r\omega_j for 0\leq j<16, and \alpha_j=c\omega_{j-16} for 16\leq j<32. If the original pair is (a_j,b_j), its rotated coordinates (a'_j,b'_j) are

\begin{pmatrix}a'_j\\b'_j\end{pmatrix}=\begin{pmatrix}\cos\alpha_j&-\sin\alpha_j\\\sin\alpha_j&\cos\alpha_j\end{pmatrix}\begin{pmatrix}a_j\\b_j\end{pmatrix}.

For a hand-chosen pair (1,0) at patch (1,2), the first row-frequency pair becomes approximately (.5403,.8415), while the first column-frequency pair becomes approximately (-.4161,.9093). The two angles distinguish the axes. Query and key rotations then make their dot products depend on relative row and column displacements, by the same rotation identity as one-dimensional RoPE.

Rearrange nine patches before projecting

The visual encoder has made one feature row per patch. Sending all of them through every language layer would make a high-resolution image a long sequence. Before the language model reads it, V4.1 collects each three-by-three neighborhood into a wider row. This first step preserves the coordinates; the following learned map reduces their width.

After the vision layers, there is still one width-d_v=1024 feature row per patch. Passing all those rows to the language model would spend a language-sequence position on every patch. Pixel unshuffle instead groups a 3\times3 neighbourhood into one wider vector. This rearranges values; it does not average the neighbourhood. If the patch grid has height H_p and width W_p, its grid shape changes as follows:

(H_p,W_p,d_v)\;\longrightarrow\;\left(\left\lceil H_p/3\right\rceil,\left\lceil W_p/3\right\rceil,9d_v\right).

The ceiling brackets round up to the next integer: a grid of four rows needs two groups of three, with empty locations padded to complete the final group. The feature width grows by nine because all nine rows' coordinates remain available inside each group. The number of grid positions shrinks before the learned projector reduces feature width.

Label the positions of a six-by-six patch grid by row and column. Its top-left group contains (0,0),(0,1),(0,2),(1,0),\ldots,(2,2). Unshuffle collects the values from those nine rows into one wider vector at output position (0,0); we will trace its exact scalar-coordinate order next. The neighbouring output position contains source rows 0 through 2 and columns 3 through 5. The six-by-six grid becomes a two-by-two grid, retaining all 36 rows' coordinates in the wider channels. Reduction occurs in the learned projection that follows.

Padding is needed when a patch-grid dimension is not divisible by three. After unshuffle, a learned projector takes width 9\cdot1024=9216 to the language width 5,120. It applies an affine map, the coordinatewise GELU activation, then another affine map. An affine map includes a matrix multiplication and a learned bias. GELU multiplies a scalar a by \Phi(a), the standard normal distribution's cumulative probability through a; for example, it sends 0 to 0 and 1 to approximately .8413. The projector therefore combines channels with a nonlinearity between its two learned maps. The vision layers use a different activation construction, SwiGLU, developed above.

The precise grouping and image span

We have decided which nine patches belong together. Their scalar coordinates still need a definite order, because the projector assigns a different weight to each input coordinate. The output groups themselves follow row-major spatial order. Inside one group, the released unfold operation visits all nine spatial offsets for feature channel zero first, then the nine offsets for feature channel one, and so on.

Write F_{r,c,k} for feature channel k at padded grid row r, column c. An output group at row i, column j starts at source coordinate (3i,3j). Its local row and column offsets are a,b\in\{0,1,2\}. For each fixed channel k, their row-major number is 3a+b, from zero through eight. There are nine entries for every preceding channel, so this scalar's destination in the packed width-9216 row u is 9k+3a+b:

u_{9k+3a+b}=F_{3i+a,\,3j+b,\,k},\qquad 0\leq k<1024,\quad 0\leq a,b<3.

At output group (0,0), channel k=1 and offsets (a,b)=(2,0) therefore send F_{2,0,1} to packed coordinate 9+6=15. No value is averaged or newly learned in this step. It is a permutation of the padded source coordinates. Concatenating nine complete width-1024 vectors would produce a different permutation and would require correspondingly permuted projector weights.

Now let W_1\in\mathbb R^{9216\times5120} and W_2\in\mathbb R^{5120\times5120} be the projector's learned matrices, with width-5120 biases b_1,b_2. Its output row is \operatorname{GELU}(uW_1+b_1)W_2+b_2. Rearrangement preserved all padded coordinates; this learned nonlinear map is where they are reduced to the language model's representation width.

For a resulting grid of H_m\times W_m visual rows, the language input reserves one start position, each row's W_m visual positions followed by a newline, and one end position. The count is H_m(W_m+1)+2. A two-by-two grid therefore occupies eight sequence positions: start, two features, newline, two features, newline, end. All eight carry the configured image token ID 129264 in the integer input; token types distinguish their roles. The embedding merge replaces features and learned delimiter rows accordingly. Images must be merged in the initial prefill chunk in this reference interface.

Visual embeddings enter the language input

At this point a visual row has width 5,120, matching a text embedding. We still need to decide where it enters the sequence. The reserved image span supplies those positions, so a language query can read the image and the question in their intended order.

The language model finally receives one sequence containing two kinds of learned row: ordinary token embeddings and projected visual features. The visual rows replace the reserved image-span positions; they are not converted into recognized words first. Delimiter and newline rows mark the span's layout. From this point onward, language attention can combine those rows with the question.

Ordering is part of the interface. A correct image and a correct projector can still produce the wrong input if patches are packed column-major while the language span expects row-major order. The count of produced vectors must also match the number of positions reserved for them.

Image preprocessing is therefore architectural input handling. Resizing, aspect-ratio constraints, patch padding and image-token IDs must agree with the released protocol. A raw tensor with the right final shape is not sufficient evidence of a correct image pathway.

Routing and memory see different token types

Image and text representations can produce different expert loads. Modality-aware balancing keeps separate correction biases when selecting experts, while retaining the original affinities as mixture weights. Aggregating the load into one count could hide a large imbalance for one modality.

Conditional n-gram memory has another boundary: image positions are not normal text suffixes. The image/text mask controls expert-bias selection and memory participation. Main attention derives its causal and local-window visibility from positions, rather than using that modality mask to decide what is in the past.

A coordinate-labelled grid makes ordering errors visible: swapping two source patches changes known slices of the packed vector. A text-only sequence should bypass the visual pathway, while multiple images require distinct reserved spans with matching vector counts. These layout properties can be established with synthetic inputs before trained weights are used for visual recognition.
