Immutable source revisions

A repository's current default branch can change after an explanation is written. The initial source capture therefore pins a revision for each model repository and records the exact files used: model cards, configuration, minimal model code, inference instructions and licenses. No weights were downloaded. Each manifest entry includes a SHA-256 content hash and an immutable URL, allowing a later reader to distinguish a changed source file from a changed interpretation of the same file.

A shape reference for implementation

The equations use small dimensions to make entries visible; an implementation must ultimately use a mutually compatible set of dimensions. The table collects selected fields from the pinned inference configurations. Hidden width is the width of one residual stream, while main head width is the width used in a query–KV comparison. Query latent width is the intermediate width before query-head expansion. Keeping those three roles separate explains why a shared KV can be much narrower than the combined query output.

The configuration's compression arrays also include auxiliary prediction or drafting entries after the backbone. Their array length therefore does not directly give the number of backbone blocks. The backbone counts below refer only to the main layer stack.

A full-width main query tensor can be much larger than its stored shared KV. For V4 Flash, 64 heads of width 512 give 32,768 query coordinates per token, while one main KV entry is width 512. The grouped output map reduces each eight-head group from 4,096 to 1,024 coordinates before its final projection.

Reference code and production claims

Several source boundaries affect what a reproduction can claim. The minimal V4.1 forward visits the full backbone rather than demonstrating optimized CED prefill. Its hierarchical scorer masks after a full comparison, rather than demonstrating gather-before-score savings. Its quantize/dequantize buffers do not demonstrate physically packed FP4 allocation. Its draft path does not include a complete verifier or scheduler.

These differences determine which comparisons are meaningful. A component reference can establish an attention or quantization calculation, while a serving claim also requires the corresponding schedule, allocation and state transitions. Those additional paths must be implemented and measured explicitly.

The browser demonstrations use hand-chosen numerical examples and no model API. The downloadable records instead contain values produced by the accompanying CPU programs, prepared with coding assistance. Keeping their commands, seeds, source hashes and tests with the results lets readers repeat those calculations and inspect later corrections. Neither kind of example measures the released model's trained behaviour.
