Preparing the joint input

V4.1 is easiest to lose track of when every improvement is read in isolation. Follow one new position instead. It receives text or visual features, may retrieve an Engram value, passes through four-stream blocks, and reads the global memory available to each layer. The full pass below keeps three dependencies visible: the current residual state, the carried input-mixture coefficients and the owner of the shared cache.

V4.1 keeps the four-stream residual interface, but changes what can enter the sequence and where later layers obtain their memory. Begin with token IDs and an aligned record identifying text and image-span positions. Text positions receive their ordinary embedding rows. An image is encoded by the vision transformer, rearranged into wider visual vectors and projected to width 5120. Those vectors replace the reserved image positions; learned vectors supply image-start, image-end and newline positions.

Fix the model width d=5120 and vocabulary size V=129280. For a batch of B sequences with T input positions, the merged embedding array has shape B\times T\times d. Its image/text record has one entry per sequence position, so an image vector replaces exactly the row reserved for it. There is no conversion from its continuous features to a new text token ID.

Only after that merge does the model repeat each width-d row into four residual streams, giving shape B\times T\times4\times d. N-gram addresses can be computed from the token IDs alongside this preparation. Image-span positions, including delimiters, are excluded from Engram, and lookback stops at their boundary. The hidden states later supply Engram's contextual gates. We will follow one receiving position below and suppress its batch and position indices; a four-stream state there is a matrix of shape 4\times d.

These parallel inputs have different meanings. Visual features replace particular initial embedding rows. Engram contributes a gated residual addition at its designated layers. Neither operation changes which earlier token positions are causally visible to language attention.

Carrying the input mixture between sublayers

After embedding and optional image replacement, each token has four residual streams. Engram can add a context-gated value at its two configured layers. The attention update then reads one mixture using the carried coefficients, and predicts the mixture needed by the next update. This is the Day 8 timing inside a complete block.

The residual construction needs both the four streams and a way to collapse them into one sublayer input. In the V4 construction, the current streams first determine their collapse coefficients. That prediction reduces across all feature coordinates, so input mixing must wait for the reduction to finish. Single-Pass mHC shifts this one dependency: use collapse coefficients already supplied by the previous sublayer, while computing new coefficients for later use. This permits a tile of the residual to contribute to input mixing as it is read, rather than requiring another full read after the new coefficients become available.

Number layers l=0,\ldots,39. Let X_l\in\mathbb R^{4\times d} be the incoming residual at our receiving position. Write R_l for the same state after the optional Engram addition at this layer; when Engram is absent, R_l=X_l. Attention produces the intermediate four-stream state Y_l, and the expert sublayer produces the next incoming state X_{l+1}.

Superscripts A and F below label attention and feed-forward sublayers; they are not powers. Each predictor \mathcal H_l^A or \mathcal H_l^F uses the normalized projection and Sinkhorn construction from the residual chapter. It returns three objects with different jobs: input mixture A_l\in\mathbb R^{1\times4}, residual transport B_l\in\mathbb R^{4\times4}, and output-injection gains C_l\in\mathbb R^{4\times1}. Only the residual transport is constrained to be approximately doubly stochastic; the other two are sigmoid-derived gains.

The normalized attention and MoE functions each take one width-d row and return one width-d row. The two learned operators \operatorname{Norm}_l^A and \operatorname{Norm}_l^F are RMSNorm across that row's d coordinates. Their statistics differ from the coefficient predictors' RMS statistic across all 4d residual coordinates. With these shapes fixed, the attention update is

(A_l^A,B_l^A,C_l^A)=\mathcal H_l^A(R_l),\qquad Y_l=B_l^AR_l+C_l^A\operatorname{Attn}_l\!\left(\operatorname{Norm}_l^A(A_{l-1}^FR_l)\right).

The left term mixes the four old streams. In the right term, the previous FFN's mixture A_{l-1}^F first collapses R_l to a 1\times d row; normalization and attention transform it; the current 4\times1 gains expand its contribution back to four streams. For layer zero, use the initial mixture A_{-1}^F=(1,0,0,0). The expert update then uses the mixture just predicted by attention:

(A_l^F,B_l^F,C_l^F)=\mathcal H_l^F(Y_l),\qquad X_{l+1}=B_l^FY_l+C_l^F\operatorname{MoE}_l\!\left(\operatorname{Norm}_l^F(A_l^AY_l)\right).

The first attention sublayer uses the initial one-hot mixture in place of A_{-1}^F. Each expert sublayer consumes the mixture predicted by its layer's attention sublayer. The expert sublayer's new mixture is carried to the next layer's attention. The transport and output-injection coefficients remain attached to their current residual update.

The matrices B_l here use output streams as rows and input streams as columns, so multiplication acts on the left of the residual. The source's stored comb array uses the transposed input/output convention. The coefficient delay is also substantive: substituting the freshly predicted A_l^A for the carried A_{l-1}^F would restore a different computation.

Engram, when present at layers 1 and 14, has already updated R_l before both coefficient prediction and the attention input collapse. Its value can therefore affect both. After the final layer, the last carried input mixture also reduces the final residual streams. Unlike the V4 head, this V4.1 readout does not introduce a separate head-mixture predictor in the pinned minimal source.

The attention path at width 5120

The block now has a prepared attention input. The ownership mode decides which work it must perform on history: create memory, reindex existing memory, or reuse both memory and addresses. Its current main query and local entry are required in all three cases.

Now follow the width-d row received by \operatorname{Attn}_l. Call it x\in\mathbb R^{5120}. Instead of projecting it directly to all query-head coordinates, the layer first uses a 5120\times1280 map and learned RMSNorm to form a smaller intermediate row, the query latent r\in\mathbb R^{1280}. A 1280\times32768 map expands that same row to 64\cdot512 coordinates, reshaped as 64 main query heads of width 512. Full and Reindex layers also obtain their smaller index-query heads from r, as developed in the reuse chapter.

The expanded main queries receive partial RoPE, rotating only their final 64 coordinates at the receiving position. In this V4.1 implementation they do so directly: V4's additional unweighted normalization within every expanded main query head is absent. The RMSNorm on the width-1280 latent remains. Those two normalization locations must not be conflated.

Every layer also projects its own local width-512 shared KV, normalizes it and applies position. Its recent 128 positions include the current token. The global branch depends on the static ownership schedule: a Full layer creates entries and index keys, a Reindex layer reads those keys but chooses fresh addresses, and a Reuse layer reads both the entries and the most recent addresses. Each still computes fresh main-attention logits.

At a cache owner, CSA2 first produces the normalized compressed main latent. An index-key projection reads that latent before main-KV RoPE. Main KV and index K then receive their respective positional and numerical transforms. This differs from V4, whose indexer has a separate hidden-state compressor. A ratio-one owner has no multi-token gate softmax; it projects and normalizes one entry per source row.

Let \mathcal J be the allowed list of local and selected global entries for this receiving position. Each stored width-512 vector c_j, for j\in\mathcal J, acts as both key and value. For head h, let q_h be its rotated query and \eta_h its learned attention-sink logit. The main comparison and value sum are

s_{h,j}=\frac{\langle q_h,c_j\rangle}{\sqrt{512}},\qquad o_h=\frac{\sum_{j\in\mathcal J}e^{s_{h,j}}c_j}{e^{\eta_h}+\sum_{j\in\mathcal J}e^{s_{h,j}}}.

The sink supplies extra normalization mass with no transmitted value. The sum still has width 512, and queries with the same address list can give different weights. Apply inverse RoPE at the receiving position to each output's final 64 coordinates. Then group the 64 heads into eight groups of eight: each group has 8\cdot512=4096 coordinates and its own 4096\times1024 map. Concatenating the eight resulting rows gives width 8192. A final 8192\times5120 map returns the attention result consumed by the residual update above.

These normalization, source and readout differences follow the pinned Attention, Block and Transformer.

Reading the prompt and continuing it

The reported CED design separates a 20-layer causal encoder from a 20-layer decoder. The encoder reads the prompt and supplies the representation from which decoder global memory is constructed. The decoder's evolving states supply its queries and its layer-local attention. This learned source dependency makes an encoder-heavy prompt schedule possible; it does not follow merely from labelling the lower half of a conventional stack an encoder.

The minimal released Python forward exposes a different execution boundary. It visits every backbone layer, and its Full attention layers construct global state from their current sublayer inputs. It does not expose an explicit final-encoder-memory argument to decoder global owners or implement the report's prompt-skipping schedule. Accordingly, there are two paths to keep visible when reading the sources: the report's optimized CED memory construction and the minimal all-layer reference. Running the latter establishes neither the former's work count nor its replay behavior.

Within the released ownership schedule, layer 20 becomes the decoder global-cache owner. Layer 24 creates a fresh selection against that memory; layer 27 reuses layer 24's addresses while forming its own main queries. Later Reindex layers can select from the larger candidate pool established at layer 20. Main attention probabilities are recalculated even where integer addresses are reused.

On resumption, the serving design can retain global memory and reconstruct a bounded tail of local state. Existing prefix-global entries must remain the retained prefix entries during replay. The approximation concerns reconstructed local history, and it can subsequently affect newly appended state. A fresh append, a replayed prefix and a speculative branch therefore need distinct write policies.

The prediction head and the drafting branch

The backbone can now predict one token. DSpark branches from selected backbone features to propose several further tokens. Follow the ordinary readout first; the draft branch uses those features as evidence and still requires verification before proposals become history.

After layer 39, the current residual is X_{40}\in\mathbb R^{4\times5120} and the last FFN has supplied A_{39}^F\in\mathbb R^{1\times4}. Their product gives the readout row z=A_{39}^FX_{40}. Final learned RMSNorm acts across its 5120 coordinates. A distinct vocabulary matrix W_{\mathrm{vocab}}\in\mathbb R^{5120\times129280} then gives logits \ell=\operatorname{RMSNorm}(z)W_{\mathrm{vocab}}, one scalar per possible next token.

These are scores, rather than token identifiers or decoded characters. The selected sampling rule turns them into a next-token ID, and tokenizer decoding turns a sequence of IDs into text. The minimal forward calls its sampling function and returns an ID alongside the logits. For the input row at position t, this ID continues the sequence at position t+1; that token becomes input on the next decoding step.

The drafting branch reads additional backbone representations: the mean over residual streams immediately before layers 37, 38 and 39. Concatenating those three width-5120 rows gives width 15,360. These are pre-block taps, not the three blocks' final outputs and not their normalized main queries.

A learned projection and normalization prepare the tapped representation for DSpark. The shared embedding lookup supplies a draft block beginning with the newly selected token and followed by noise-token slots. Three draft blocks process the speculative positions. Their heavy computation produces base vocabulary logits together; a small Markov head then conditions sampling of each draft token on the preceding sampled identifier. The confidence head reads the draft hidden state together with the corresponding Markov embedding.

The five proposed identifiers are not five verified target outputs. The verifier must compare their conditional proposal probabilities with target probabilities in sequence, preserve the accepted prefix and repair state after rejection. Confidence estimates inform how much drafting may be worthwhile; they do not replace the probability-correct acceptance rule derived earlier.

What the complete computation specifies

The complete pass now has a defined source for each input. Text IDs and pixels supply embedding rows. The evolving residual state supplies each sublayer's computation and contextual memory gates. Cache owners supply global entries; index sources supply their selected addresses; each attention layer forms its own main queries and recent local state. The final mixture supplies vocabulary scores. These dependencies specify how information reaches a prediction, while training determines what the model makes of it.

Training determines the parameters in these operations. Numerical formats determine the rounding and storage along their paths. Serving determines when permitted state can be retained, reconstructed or shared. These choices meet at defined tensor boundaries, so a changed cache source or coefficient index is an architectural change rather than a harmless implementation rearrangement.

The next chapter turns from this forward computation to the objectives and updates that choose its parameters. The later implementation and executable-miniature chapters connect the public-source description to runnable small models, with their dimensions and numerical policy stated explicitly. Their correspondence tables identify which operations are exercised; publicly unspecified training details and production-only scheduling behavior remain identified at the relevant boundary.

Check the assembled path on a small model

The released dimensions are too large for a hand trace. The downloadable six-layer miniature retains the dependencies: an encoder memory owner, a decoder owner, Reindex and Reuse consumers, four residual streams and a final vocabulary readout. Its parameters are initialized random values, so its predictions check composition rather than language ability.

Follow its zero-based layers in order: layer 1 creates encoder memory; layer 2 reuses it; layer 3 creates decoder memory; layer 4 changes the selected addresses against that memory; layer 5 reuses both. The current token still forms a fresh main query at every layer. This is a reduced schedule, not the first six layers of the released network.

Open the forward trace, select the V4.1 family, and follow the recorded input through that owner chain to the logits. Then compare a full prefix evaluation with incremental evaluation at the same positions. The recorded miniature checks find agreement within floating-point tolerance. They do not execute optimized encoder-only prefill, bounded replay or a production speculative verifier.
