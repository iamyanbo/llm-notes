Two things can be reused independently

Two consecutive layers may ask different questions about the same past. They do not necessarily need two separately stored copies of that past. After changing where global memory comes from, V4.1 changes how often it is recreated. A later layer can reuse the entries but choose new addresses, or reuse both the entries and the earlier selection.

Reusing memory need not produce the same answer. In a sink-free example, retain entries c_0=(1,0) and c_2=(1,1), omitting score scaling for this calculation. Query (1,0) assigns equal logits and returns (1,1/2). Query (0,1) assigns logits 0 and 1, returning approximately (1,.731). Both queries used the same entries and addresses. A later layer can form a different comparison against shared state.

The smaller indexer from the sparse-attention chapter supplies integer addresses for the main attention calculation. Its index keys are comparison features; the main KV entries are the vectors actually read as keys and values by the 64 main heads. A Top-K selection retains the K addresses with greatest index scores, with K=512 in V4.1. Saving those addresses is different from saving the main attention probabilities: each main query still computes new dot products and a new normalization.

CSA2 names three layer modes fixed by configuration. A Full layer creates main KV and indexer keys, and performs indexing. A Reindex layer reuses those representations but computes its own indexer query and selection. A Reuse layer uses the existing cache and the latest selection against that cache. Every mode retains its own main query and local-window state.

The released ownership schedule

Continue using zero-based layer numbers. In the pinned V4.1 configuration, global-cache owners are layers 2, 8, 14 and 20. The first three own pair-compressed encoder entries: each consecutive group of two source positions yields one entry. Layer 20 owns decoder global entries with ratio one, meaning one entry per source position. The first two backbone layers use only local attention.

Indexer-source layers are 2, 8, 14, 20, 24, 28, 32 and 36. A global layer in that list but absent from the cache-owner list is a Reindex layer. Other global layers reuse the current selection. This schedule is configuration, not an input-dependent decision to switch modes.

Layer 20 therefore creates decoder global KV, index keys and a selection. Layer 24 retains that KV and those index keys but creates a new selection. Layer 27 retains layer 20's memory and layer 24's selection. All three layers compute their own main query, so the ownership trace does not imply identical attention outputs.

CSA2's compressor has no previous-block overlap or learned within-block positional bias. Index keys are projected from the compressed main latent rather than produced by a separate hidden-state compression path. The ratio-one case reduces to a projected, normalized entry; it does not require a one-element learned softmax gate.

One completed group in a Full layer

The ownership schedule tells us where a stored entry comes from. We should also follow what that owner computes. Work at one encoder Full layer and suppress its layer and batch indices. Let x_t\in\mathbb R^{5120} be the normalized attention input at source position t. Number consecutive two-position groups by j=0,1,\ldots; group j contains rows x_{2j} and x_{2j+1}.

The compressor's content map and gate-logit map both have shape 5120\times512, acting on rows from the right. At coordinate k=0,\ldots,511, their outputs are content c_{t,k} and a scalar pooling logit z_{t,k}. Exponentiating the two logits and dividing by their sum gives nonnegative shares totaling one. Write the pooled width-512 row as u_j. Its coordinate and normalized result \bar c_j are

u_{j,k}=\frac{e^{z_{2j,k}}c_{2j,k}+e^{z_{2j+1,k}}c_{2j+1,k}}{e^{z_{2j,k}}+e^{z_{2j+1,k}}},\qquad \bar c_j=\operatorname{RMSNorm}(u_j).

Here e^z is the exponential used in softmax. If one coordinate's contents are 2 and 6 with logits 0 and \log3 (the natural logarithm), its exponentiated amounts are 1 and 3. Dividing by their sum gives shares 1/4 and 3/4, and the pooled coordinate is \tfrac14\cdot2+\tfrac34\cdot6=5. Another coordinate may use different shares.

The bar in \bar c_j marks the following learned RMSNorm, rather than another token average. This normalization divides the whole width-512 row by \sqrt{\tfrac1{512}\sum_{k=0}^{511}u_{j,k}^2+\epsilon} and then applies its learned coordinate gains, with \epsilon=10^{-20}. Pooling combines source positions; normalization controls the resulting row's scale across feature coordinates.

The group becomes visible only after its second token arrives. More generally, let r be the number of consecutive source positions per global entry and i a zero-based receiving position. There are i+1 source positions through the current token, hence \lfloor(i+1)/r\rfloor complete groups; the floor brackets discard any fractional group. At ratio two, query position 2 has seen three tokens but only one complete pair, positions 0 and 1. Query position 3 can also read the completed pair at positions 2 and 3.

Entry j uses RoPE position jr, its first source position. A ratio-one decoder owner simply projects and normalizes each input row; the pooling gate and incomplete-group state disappear.

The index key is made before the main cache is rotated

V4 built a separate compressed representation for the indexer. CSA2 can derive its smaller comparison key from the main compressor's latent instead. The reason is reuse: one completed memory entry can supply both a vector to read and a smaller vector for finding its address. The branch point must come before operations specific to the stored main vector.

A Full layer has just obtained the 512-coordinate row \bar c_j. A latent here means an intermediate representation retained for later transformations; it is not a separate kind of number. Before rotating and quantizing this main-cache row, the layer applies a separate 512\times128 row-map and index-key RMSNorm. Its width-128 output becomes the smaller comparison key k_j^I after RoPE on its final 64 coordinates and four-bit floating-point (FP4) quantization. The main row independently receives RoPE on its final 64 coordinates and its own cache quantization. The precision chapter develops their group scales; the important dependency here is that the index-key projection reads the main latent before those transforms.

Now follow the receiving side. Its current normalized attention input is x_i\in\mathbb R^{5120}. A learned matrix W_a\in\mathbb R^{5120\times1280} reduces that row to a width-1280 intermediate, and a learned RMSNorm across those 1280 coordinates gives r_i. Both the main query and the index query expand from this same intermediate:

r_i=\operatorname{RMSNorm}(x_iW_a)\in\mathbb R^{1280}.

In Full and Reindex modes, an index-query map of shape 1280\times4096 produces 32\cdot128 coordinates, reshaped into 32 query heads of width 128. After receiving-position RoPE and FP4 quantization, denote head h=0,\ldots,31 by q^I_{i,h}\in\mathbb R^{128}. A second map W_w\in\mathbb R^{5120\times32} supplies one learned head weight w_{i,h}, scaled by 1/(\sqrt{128}\sqrt{32}). The index score for global entry j is

s_{i,j}=\sum_{h=0}^{31}w_{i,h}\operatorname{ReLU}\!\left(\langle q^I_{i,h},k_j^I\rangle\right),\qquad w_i=\frac{x_iW_w}{\sqrt{128}\sqrt{32}}.

The fixed divisors scale the comparisons according to the index-head width and number of heads. They do not divide by a sum of learned head weights and do not force those weights to total one. The final sum combines 32 scalar head contributions into the single score used to rank entry j.

The angle brackets mean the dot product, a sum of 128 matching coordinate products. \operatorname{ReLU}(a)=\max(0,a) discards each negative head comparison. The head weights are neither softmax weights nor restricted to nonnegative values. In a hand-chosen two-head illustration, comparisons (2,3) and weights (.25,-.5) give .25\cdot2-.5\cdot3=-1. Thus a rectified comparison in each head does not force the combined score to be positive. Top-K ranks the combined scores; it does not send an indexer value sum to the backbone.

Reindex supplies its own x_i,r_i,q_i^I,w_i while retaining the owner's keys. Reuse supplies no new index scores. All modes separately up-project r_i to 64 main query heads of width 512 and attend to their own local KV plus the selected shared global entries. This is where the selected values actually enter the layer's representation.

A candidate pool before the later Top-K

Sharing saved memory construction, but an indexer could still compare its query against the entire history. Hierarchical indexing first keeps a coarse candidate region, then lets later indexers search within it. A relevant entry outside that region cannot be recovered by a later fine selection, so the candidate rule is part of the model's information path.

For a small case, group eight addresses into pairs \{0,1\},\{2,3\},\{4,5\},\{6,7\}. Suppose the coarse stage retains the first and third groups. A later indexer scoring (4,1,9,8,3,7,6,2) can select addresses 5 and 0 from its candidates \{0,1,4,5\}; addresses 2 and 3 remain unavailable despite their greater scores. These chosen group sizes expose the restriction before the released counts below.

Group consecutive global-cache positions into blocks of eight. A block receives the maximum of the first indexer's scores at its positions. Retain up to 2,048 causally reachable blocks, forcing inclusion of the block containing the latest reachable position. Expanding a retained block means admitting all of its reachable positions to the candidate list, rather than only the position that supplied its maximum. There are at most 2048\cdot8=16384 candidates. Later Reindex layers choose their final Top-512 within that list.

The candidate pool is not just the first layer's final 512 entries. It deliberately leaves later layers room to make a different selection. Confusing the pool with that earlier final selection would impose a stronger restriction.

A later scorer with a fixed-size candidate pool can have bounded comparison work as the context grows. The candidate-producing pass still scans the visible context. Calling the entire model's cost exactly constant would erase that pass and other sequence-dependent operations.

Logical positions and physical addresses

The sparse-attention kernel reads one concatenated KV tensor: the two lists of rows are placed end to end. During initial prefill its first part contains the local KV rows for the input chunk. During one-token decoding, that part is a ring of 128 local slots; the current position replaces the slot with the same remainder modulo 128. The global-cache slice follows it. Let n_{\mathrm{local}} be the number of rows in the first part. A global index j becomes the physical concatenated address n_{\mathrm{local}}+j; a local slot uses its address in the first part. The sentinel -1 means “no valid row,” rather than the first token or the last Python array element.

For example, with 128 local ring slots, global entry 7 is addressed as 135. It is still logical global entry 7: the offset does not change its RoPE position or source tokens. When a new Full layer replaces the shared owner, its later consumers must use the new cache, index keys and address selection together. The shared runtime publishes these states in layer order; it is not a cache manager for arbitrarily interleaved model instances.

Hierarchical candidates add another selection boundary. The first decoder Full layer computes its own final Top-512 and separately builds the block candidate mask. Later indexers search that larger mask. The training-aware candidate restriction is introduced during post-training and used during inference as well. It changes the permitted search domain, while gathering candidate keys before scoring is the implementation step that can save comparison work.

Semantic reuse and computational savings

There is a trap in implementing this saving. Score all positions, then mask those outside the candidate pool: the selected addresses can be correct while the supposedly avoided comparisons have already run. The minimal source follows that full-score-then-mask route. To save comparison work, an implementation has to gather the candidate keys before scoring them.

The dense-then-mask version and the gather-before-score version can produce the same selected addresses because they compare the same permitted keys. Their intermediate tensors differ: one contains scores for the full sequence and the other only for the candidate pool. Agreement establishes the selection calculation; a separate profile is needed to determine whether the gather and smaller comparison improve execution time.

We have separated three kinds of work that ordinary attention bundles together: creating memory, selecting addresses and reading their values. Sharing the first two still leaves each layer its own main queries and output. The next addition reuses something different: learned features associated with a short token pattern, retrieved without searching the attention history.
